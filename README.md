# WARSEED

《灰脊矿区》的当前操作闭环与开发自测步骤见 [`docs/GREY_RIDGE_OPERATION_TEST_GUIDE.md`](docs/GREY_RIDGE_OPERATION_TEST_GUIDE.md)。条件允许时的真人产品研究可使用 [`docs/PLAYTEST_PROTOCOL.md`](docs/PLAYTEST_PROTOCOL.md)，但不参与工程或发布门。

> 一款用常驻军团卡牌组织真实战场编队，并在将领 Agent 指挥与部队卡级直接操作之间切换的即时战术游戏。

## 项目定位

《WARSEED》的核心体验是“军团卡牌在实时战场上的展开”：将领卡代表具备性格和战法槽的指挥 Agent，部队卡代表持续存在的真实编队。玩家把将领拖向战区下达意图，也能选中一张部队卡，为整个编队绘制路线和阵线。

卡牌全部可见、持续存在，不抽取、不洗牌。战场损失、经历和装备会回写到同一张部队卡。玩家始终拥有最终控制权，但正式操作下限是完整部队卡，不逐个士兵微操。

## 核心支柱

1. **卡牌就是军队**：编成、战法、战损和成长都由常驻卡牌承载。
2. **真正执行意图的将领**：Agent 把目标转化为地图上可见、可解释的编队行动。
3. **两种指挥粒度**：将领级意图与部队卡级路线/阵线直接控制共存。
4. **公平而不完整的情报**：报告有来源、时间和可信度，敌方不读取隐藏真值。
5. **固定计划、可审计反应**：敌方初始方案和反应规则在开局锁定。

## 首切片摘要

- 《灰脊矿区》一张 5—8 分钟 1v1 会战地图；
- 三个自动结算的资源区、基础补给收入、人口和总部预备编制；
- 至少两名将领、四张部队卡和四张战法卡；
- 部队卡展开为不少于 40 个战场实体；
- 支持将领意图、姿态、部队卡整队选择、路线/阵线和明确归还；
- 带来源与可信度的情报，以及开局锁定计划的公平敌方 AI。

内容扩充阶段已经完成 P5 工程切片。作战区现提供《灰脊矿区》《断桥回声》《雾林输线》《黑井反击》四场正式会战；每场拥有独立内容包、三套开局前锁定计划、场景化教程文本、smoke 和确定性矩阵。《黑井反击》使用 `7168×4608` 工业战场，引入五将领/十二部队卡编成、卡牌级组织度、多轴增援、整卡有限撤出和共享军团成长确认。六步教程固定在地图外侧栏，只接受已执行命令、玩家可见快照与结算事实。P6.1—P6.4 已完成逐关教程重播、28 类上下文回执、两个隔离档的四关真实键鼠串联，以及 `1280×720` 至 `480×800` 五档关键界面矩阵。P6.5 已把接敌、集火、受压、增援、侦察、总部危机和胜负接入同一权威事件反馈层：高频声音按编队聚合并限制为三声部，关键提示可抢占，静音仍保留文本和地图效果；真实《灰脊矿区》自测分别捕获四类战斗提示，新增音频开关也再次通过五档分辨率回归。P6.6 已完成四关六策略的 `72/72` 确定性平衡审计、军团/教程/试玩记录格式冻结，以及连续两次完整 Windows 发布门；P6.1—P6.6 的工程验收已闭合。P6.7 的隔离启动、四关逐场评估、分关队列汇总和候选包入口已就绪；D-026 后真人理解度研究为可选项，不阻塞当前 R2 玩法改写。

最新产品基线已迁移为常驻军团卡牌会战，项目主场景现为《灰脊矿区》基础切片。主场景先进入 tick 0 战前军团编成：四张部队卡可改挂三名将领，三名将领可分别选择合法战法和初始姿态，并从四张卡中准确选择两张首发；指挥容量和所有非法组合由权威 `ArmyPlan` 校验，未提交合法计划前计时与战场命令均停止。默认计划以 20 个友方实体和 14 个敌方实体开始；自定义计划的人口由两张实际首发卡计算。敌方 12 人突击主力与 2 辆独立装甲先遣分别组成稳定 formation，并从“中央突击”“西线钩击”“西部佯攻”三套方案中锁定开局；计划和佯攻转向时间表都在读取任何玩家行为前按战役记录确定并写入审计日志。点击已部署部队卡会整选真实编队；预备卡既可拖给其战前所属将领，由系统在总部朝该将领目标方向选择合法展开点，也可点击后在总部附近精确指定部署点。拖给其他将领不会在会战中免费改编，而会收到结构化拒绝；合法投入统一经过命令校验、队列和 10 秒权威计时后展开为真实实体。场景已有 5/10 补给、40 人口上限、20 秒基础收入、南北总部、八分钟失败时限，以及三个可争夺、每 30 秒自动结算的战略区。空中侦察和紧急筑垒均走权威支援命令；枢机情报栏从快照显示来源、时间、估计数量、区域、方向和可信度。

《灰脊矿区》现已形成首个工程可玩切片：双语战前军团板支持编成、容量反馈、战法/姿态和首发/预备配置；正式选择粒度固定为整张部队卡，`F3` 才开放个体诊断。玩家可把将领卡直接拖向战区，并在任务建立后拖动地图目标环重新定向；预备部队卡也可拖给战前所属将领投入增援，合法与冲突目标分别提供明确预览。所有这些交互都只提交合法命令，不提前修改权威状态。玩家也可接管整卡、绘制或编辑最多八段航路和最终阵线，再明确归还具名将领。三名将领拥有独立任务、五种姿态和四张可装配战法；四类战团受到开阔地、废墟和林地规则影响。西部矿地、中央废墟和东部林地使用不同的程序化纹理与双语地形标签；合法命令、拒绝命令和新敌情各有可区分的短提示音。敌方反应表在开局锁定，只读取其阵营合法情报。战局结束后会进入军团结算：幸存人数、战损、补充点、功勋和战役时间写入 `user://grey_ridge_roster.json`；玩家可补员、授予带部署/补员代价的集体嘉奖、安装带速度代价的强化侧裙，再返回军团编成调整下一局计划。

路线编辑现可直接拖动已提交航路点与阵线端点，并显示由来路推导的正面箭头和按整卡成员射程计算的预测交战扇区。军团板会从权威快照显示每名将领的当前行动、结构化原因、预计到达区间、风险及其情报依据和退出条件，覆盖姿态、战法准备、接敌/规避、任务受阻、整卡接管和归队；风险只读取阵营已知接触与未过期报告，不读取隐藏真值。交替掩护只计算已部署部队，脱离姿态会选择可容纳整队展开的总部集结地域。常见 A/B/C 与三种自由命令组合现已对三套锁定敌方计划形成 6×3 确定性场景矩阵，校验权威状态哈希与敌方决策来源；将领会为整卡寻找目标区内可展开位置，新部署预备队会继承将领当前目标。每局《灰脊矿区》试玩会在本地 `user://playtests/` 保存版本化事件记录，并在战后显示战前编成耗时、计划变更/非法状态次数、首次有效命令、改令率、情报响应时间、直接控制比例、接管/归还和单兵诊断尝试；主观理解项目只有在可选真人研究中才由观察员填写。本机 Windows 完整 HUD 实渲中，80/120 实体 30 秒常态帧 P95 为 14.396/19.931 ms、模拟 P95 为 6.892/10.919 ms；80 实体正式门通过，120 实体扩展测量未达到 60 FPS 数值线。80/120 实体加 160 常驻弹丸的帧 P95 为 16.243/21.869 ms，同样只作为峰值压力证据。480 秒长局既有基线完成 4800/4800 tick，帧 P95 为 9.198 ms、模拟 P95 为 5.030 ms，路径失败、未决权威输入、孤儿节点增长和资源增长均为 0。可选真人研究、正式关卡 80—120 实体实战内容和最终美术仍未完成。详细边界见[当前进展与下一步](docs/STATUS_AND_NEXT_STEPS.md)。

技术底座的稳定性与自主 AI 已将渲染目标设为 120 FPS（最低验收 60 FPS），权威模拟保持 10 Hz。表现层每个权威快照只同步一次代理和 HUD；战争迷雾区分可见敌军、情报残影和确认残骸。旧参谋部的经济/固守/进攻方针、预算仲裁、侦察规避和失联搜索继续作为新将领 Agent 与公平敌方计划的实现参考。

## 本地复现

1. 安装 Godot `4.6.3-stable`（Windows 推荐 Mono 构建，并安装同版本 export templates）。
2. 克隆仓库并从 Godot Project Manager 导入仓库根目录的 `project.godot`。
3. 按 `F6/F5` 或直接运行项目；主场景为 `scenes/game/battle_selector.tscn`，可选择《灰脊矿区》《断桥回声》《雾林输线》或《黑井反击》。`game_root.tscn` 保留为技术回归基底场景。

推荐使用统一发布验收入口（将 `<godot-console>` 替换为本机 Godot console 路径）：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\verify_grey_ridge_release.ps1 `
  -GodotConsolePath <godot-console>
```

该入口会严格串行执行编辑器导入、两轮 18 套测试、旧切片、四场会战 smoke、逐关确定性矩阵、四关 72 案例发布平衡审计、灰脊 `5 x 3 x 2` 完整策略质量矩阵、实体基准、试玩工具烟测、Windows debug export、导出包隔离启动和试玩包校验。CI 使用同一脚本，避免本地与远端维护不同的验收清单。

需要单独定位问题时，可分别运行：

```powershell
& <godot-console> --headless --editor --path . --quit
& <godot-console> --headless --path . --script res://tests/test_runner.gd
& <godot-console> --headless --path . --script res://tests/vertical_slice_smoke.gd
& <godot-console> --headless --path . --script res://tests/grey_ridge_smoke.gd

powershell -ExecutionPolicy Bypass -File .\tests\tools\playtest_report_smoke.ps1
powershell -ExecutionPolicy Bypass -File .\tests\tools\isolated_playtest_launcher_smoke.ps1
powershell -ExecutionPolicy Bypass -File .\tests\tools\playtest_kit_smoke.ps1
powershell -ExecutionPolicy Bypass -File .\tests\tools\playtest_cohort_smoke.ps1
```
