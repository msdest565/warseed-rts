# 《灰脊矿区》Windows 实渲性能基线

> 最近测量日期：2026-08-18。该文档描述工程压力夹具，不代表完整 MVP 已有 80—120 个实战内容实体。D-026 后真人研究不再是工程或发布门。

## 1. 测试环境

- Godot `4.6.3-stable.mono`，GL Compatibility；
- Windows，Intel Arc Graphics；
- 2560×1600 全屏，完整战场与完整 HUD；
- VSync 关闭；常态/峰值测量前的空场景帧 P95 分别为 8.488/8.512 ms，环境具备 60 FPS 测量条件；
- 权威模拟保持 10 Hz；性能夹具在中央通道制造多编队交叉、恢复与改令压力；
- 表现层只消费本地阵营快照，不读取隐藏真值。

基准脚本：`tests/performance/grey_ridge_windows_render_benchmark.gd`。结果写入 `user://performance/grey_ridge_windows_render_latest.json`，截图按实体数、弹丸数和诊断开关分别命名，避免互相覆盖。

## 2. 常态结果

30 秒样本，不注入人工弹丸：

| 实体 | 帧平均 | 帧 P95 | 模拟 P95 | 输入到表现 P95 | 路径失败 | 结论 |
|---:|---:|---:|---:|---:|---:|---|
| 80 | 9.335 ms | 14.396 ms | 6.892 ms | 105.584 ms | 1 | 通过正式 16.667 ms 帧门 |
| 120 | 10.982 ms | 19.931 ms | 10.919 ms | 108.152 ms | 3 | 未达到 60 FPS 数值线；当前为扩展测量 |

正式必过门当前只适用于“80 实体、无人工常驻弹丸”。120 实体是扩展测量，不以“不适用”冒充通过。

## 3. 峰值压力

15 秒样本，注入并维持 160 个弹丸：

| 实体 | 帧平均 | 帧 P95 | 模拟 P95 | 输入到表现 P95 | 弹丸峰值 |
|---:|---:|---:|---:|---:|---:|
| 80 | 10.165 ms | 16.243 ms | 7.410 ms | 105.415 ms | 160 |
| 120 | 11.765 ms | 21.869 ms | 10.760 ms | 105.488 ms | 160 |

该结果用于暴露峰值成本，不属于常态 60 FPS 验收门。它证明批量弹丸路径非空且输入仍低于 150 ms；80 实体峰值仍低于 16.667 ms，120 实体峰值则没有达到该数值线。120+160 仍是短时扩展压力样本，不据此扩大正式关卡或验收范围。

## 4. 八分钟长局

80 实体、无人工弹丸、完整 HUD/战场的 480 秒墙钟样本已经通过长期稳定性门：

| 指标 | 结果 |
|---|---:|
| 权威 tick | 4800/4800，完成率 1.0 |
| 帧平均 / P95 / 最大 | 8.333 / 9.198 / 30.865 ms |
| 模拟平均 / P95 / 最大 | 3.860 / 5.030 / 23.098 ms |
| 输入到表现 P95 | 102.080 ms |
| 已确认表现输入 | 319；权威/表现未决 0/0 |
| 路径失败 | 0 |
| 静态内存增长 | 13,086,476 bytes |
| 节点 / 孤儿节点 / 资源增长 | 32 / 0 / 0 |

节点增长来自长局中逐步进入阵营知识、随后建立表现代理的单位；孤儿节点和资源数没有增长。该结果证明 80 实体工程压力世界可持续运行完整八分钟，不代表正式关卡已经具备 80 个内容实体，也不替代陌生玩家完成一局的人工证据。

## 5. 本轮优化

- 单位、弹丸和阻断格改为 `MultiMeshInstance2D` 批量绘制，同时保留一实体一 `UnitProxy` 的选择和映射语义；
- 军团板不再因 ETA、战损或倒计时变化而销毁重建全部卡牌；
- HUD 更新拆成三个表现帧，避免权威 tick 与全部面板同帧集中刷新；
- tick 内 Agent 连续命令复用同一权威阵营知识，首 tick、支援、建造和增援展开仍会在 Agent 决策前刷新；
- `FactionKnowledge` 在知识更新时维护按实体 ID 排序的当前可见敌军索引；灰脊敌方反应直接读取对应 `KnowledgeContact`，不再每 tick 构造完整敌方阵营快照；
- 战略攻击、防守、侦察、威胁选择与火力准备共享同一份合法阵营知识，不再由每个任务重复构造世界快照；侦察规避使用接触记录中观察时的射程；
- 当前可见接触在后续 tick 原位刷新，避免为同一敌军持续分配新的 `KnowledgeContact`，历史位置与快照拷贝语义保持不变；
- 表现层在每个新权威快照到达时一次性建立上一帧可见单位与弹丸的位置索引，渲染帧插值由逐实体线性扫描改为常数时间查找；单位与弹丸的 `PackedFloat32Array` MultiMesh 缓冲只在数量变化时调整长度，随后原位复用；
- 批量模式下隐藏的 `UnitProxy` 不再重复接收快照和重绘；选择刷新改用稳定索引，并跳过同一帧重复的插值批处理；
- 战争迷雾只降级上一 tick 真正可见的格子，并用整数距离更新圆形视野；
- 地形效果的第二次更新只处理移动后实际跨越地形边界的单位。

上述修改保持 `GameCommand -> Validator -> Queue -> SimulationWorld -> Snapshot/Event -> Presentation` 边界，四关确定性矩阵仍通过。扩大后的战场曾因逐格绘制阻断区产生约 2500 个 draw call；阻断格批处理后常态平均 draw call 降至约 709/724。最新 80/120 实体常态帧 P95 为 14.396/19.931 ms，80/120+160 弹丸帧 P95 为 16.243/21.869 ms。80 实体常态正式门仍通过；120 实体常态和峰值均未达到 16.667 ms 数值线，因此只保留为有明确失败结论的扩展测量。

## 6. 尚未完成

- 120 实体常态与 120 实体加 160 常驻弹丸均未达到本机 60 FPS P95 数值线，仍需继续优化或明确排除在 MVP 正式规模之外；
- 正式关卡 48 实体内容的人工八分钟会战仍未完成；已通过的是 80 实体确定性工程压力长局；
- 当前正式关卡满预备投入仍只有 48 个真实实体，80/120 来自确定性工程压力夹具，不是完整 MVP 内容；
- 陌生玩家试玩为可选产品研究；性能测试既不能替代主观体验结论，也不再等待真人证据放行。

## 7. 复现命令

```powershell
& <godot-console> --path . --resolution 1280x720 `
  --script res://tests/performance/grey_ridge_windows_render_benchmark.gd `
  -- --entities=80,120 --projectiles=0 --sample-seconds=30

& <godot-console> --path . --resolution 1280x720 `
  --script res://tests/performance/grey_ridge_windows_render_benchmark.gd `
  -- --entities=80,120 --projectiles=160 --sample-seconds=15

& <godot-console> --path . --resolution 1280x720 `
  --script res://tests/performance/grey_ridge_windows_render_benchmark.gd `
  -- --entities=80 --projectiles=0 --sample-seconds=480
```

禁止使用 `--headless` 运行该脚本。`--hide-hud`、`--hide-battlefield` 和 `--disable-game-root-process` 只用于诊断，不得作为正式结果。
