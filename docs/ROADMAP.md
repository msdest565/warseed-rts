# WARSEED 开发路线图

## 路线图原则

- 先验证独特体验，再扩充内容；
- 每个阶段以可观察的退出条件结束；
- 团队规模和投入时间未定前，不虚构日历工期；
- 核心系统必须在关闭语言模型时仍可运行；
- 优先解决控制权、任务透明度与可测试性。

## 阶段 0：产品规格冻结

### 目标

把概念统一为一套完整、内部一致、可验收的 MVP 规格。

### 工作项

- 固定开局配置、地图区域和胜负规则；
- 建立单位与建筑属性表初稿；
- 定义资源价格、采集效率、生产时间和战斗节奏；
- 固定结构化高层命令及其参数；
- 定义控制权、接管、归队和命令取消规则；
- 为每个 Agent 写出行为边界和受阻原因；
- 定义试玩问题和数据指标；
- 将未决问题记录到决策日志。

### 退出条件

不依赖口头补充，即可描述并验收一局完整的垂直切片。

## 阶段 1：Godot 技术基线与工程引导

### 目标

在已批准 Godot 的前提下，锁定可复现技术基线并建立可运行的最小工程。

### 工作项

- 安装并锁定精确 `4.6.x-stable`，让编辑器、测试和导出模板一致；
- 创建 Windows-first、2D top-down Godot 工程及约定目录；
- 建立 10 Hz `SimulationWorld`、`SimulationHost` 和渲染插值；
- 验证 UI 与测试 Agent 共享 `GameCommand`、`CommandValidator` 和 `CommandQueue`；
- 完成 `TileMapLayer` 到逻辑格/`AStarGrid2D` 的小型导航 spike；
- 验证 formation slots、简单 separation 和狭窄通道降级；
- 验证 typed custom `Resource`、`.tres` 加载和引用校验；
- 评估 GUT 与项目自有 headless runner，确认退出码和 CI 输出；
- 添加与实际工程一致的 Godot 专用 `.gitignore`；
- 创建 Windows debug export preset，初期不启用 Git LFS。

### 退出条件

阶段 1 包含 [Godot 技术方案](TECHNICAL_PLAN.md) 的 Gate A，并额外完成导航/编队 spike：

- 最小工程能由锁定版本打开，且没有生成缓存进入 Git；
- headless 测试可运行并返回可靠退出码；
- 测试 UI 与测试 Agent 能通过同一验证器提交等价命令；
- 单位能沿逻辑格路径移动并保持基础 formation slots；
- Windows debug build 可启动；
- 精确版本、测试 runner 结论和工程结构已更新到决策记录。

## 阶段 2：纯手动 RTS 原型

### 目标

证明没有 Agent 时，基础游戏也能完整游玩。

### 工作项

- 2D 地图、相机移动和缩放；
- 点选、框选、右键命令与数字编队；
- 单位移动、寻路、攻击、伤害与死亡；
- 矿车采集、返仓与资源消费；
- 工程车建造、建筑生产队列和维修；
- 战争迷雾与最后已知位置；
- 指挥中心胜负条件；
- 基础调试覆盖层与事件日志。

### 退出条件

玩家可以完全手动完成一场短局；核心模拟可加速和复现，关键规则有自动测试。

## 阶段 3：任务与控制权垂直验证

### 目标

先解决“谁在控制单位”和“任务如何安全执行”。

### 工作项

- 战略目标、Agent 任务、单位动作三层结构；
- 统一任务生命周期与受阻原因；
- 单位控制权状态和命令优先级；
- 玩家临时接管；
- 返回原编队、留在当前位置、加入其他编队和持续手动；
- 任务暂停、取消、修改与恢复；
- 目标、路线、阶段与参与单位可视化；
- 使用简单测试 Agent 驱动一支编队。

### 退出条件

Agent 带队移动时，玩家能接管一个成员、完成操作并明确归队；Agent 全程不抢命令，原任务能合理继续或报告缺员。

## 阶段 4：工业主管

### 目标

验证经济委托是否减少重复操作。

### 工作项

- 矿车自动循环采集与遇敌撤回；
- 全局经济/军事/防守/均衡优先级；
- 任务资源预留；
- 按指定计划生产单位；
- 在指定区域选择合法建筑位置并显示蓝图；
- 调度工程车施工；
- 报告资源不足、无可用单位和路径不可达。

### 退出条件

“发展经济/矿区”能从采集开始，完成第二辆矿车和指定建筑或明确报告受阻；玩家直接调整矿车或队列后不会被立即抵消。

## 阶段 5：战场将领

### 目标

验证军事委托与关键微操能够共存。

### 工作项

- 分配战斗单位与建立单一编队；
- 侦察、集结、防守区域和沿路线进攻；
- 防守半径与禁止过度追击；
- 突击车前排、导弹车后排的基础阵型；
- 按损失阈值撤退；
- 接敌、损失、增援需求和完成报告；
- 被玩家接管成员的缺员处理。

### 退出条件

“留守两辆突击车，其余从西侧进攻”能够正确分配、集结、行军和交战；玩家接管导弹车后可稳定归队。

## 阶段 6：主 AI 与指挥界面

### 目标

形成单一入口、多角色执行的完整指挥体验。

### 工作项

- 结构化命令面板与地图目标选择；
- 使用任务模板完成目标校验、拆分和分派；
- 跨 Agent 资源与单位冲突检测；
- 状态、敌情、生产和编队摘要；
- 只在真正无法自动解决的冲突中请求玩家优先级；
- Agent 详情、任务队列和事件记录。

### 退出条件

玩家主要通过参谋长发令，可以查看和干预下属任务，且不被普通执行弹窗打断。

## 垂直切片整体验收门

阶段 3—6 的能力先汇合为一个 5—8 分钟切片，而不是直接扩展到完整对局。切片只要求“发展矿区、守住区域、攻击目标”三个高层命令，并必须包含玩家接管导弹车、完成操作、明确归队且原任务继续。任务目标、路线、阶段、参与者和受阻原因必须可见；离线、无 LLM、headless 回归与 Windows debug export 均通过后，才进入 15—20 分钟完整 MVP 扩展。

## 阶段 7：敌方 AI 与完整对局

### 目标

提供稳定、可重复、会迫使玩家调整重点的压力。

### 工作项

- 阶段状态机：发展、侦察、骚扰、争矿、扩军、进攻、回防；
- 根据最后已知信息选择骚扰和进攻目标；
- 基础难度参数；
- 至少一次矿车威胁、中央矿争夺和基地攻防；
- 完整 15—20 分钟经济与战斗曲线调优。

### 退出条件

敌方能稳定打完一局，不依赖全图精确作弊，并迫使玩家在经济、进攻和防守间改变重点。

## 阶段 8：全权副官与教学

### 目标

让新人观察组织运作，并从任意环节插手。

### 工作项

- 稳健默认经济与防守策略；
- 中央矿争夺与首次进攻时机；
- 玩家高层命令覆盖默认策略；
- 任意单位接管与重新委托；
- 清晰展示“当前谁控制什么”。

### 退出条件

不操作时，AI 能完成一场基础对局；玩家介入后，默认策略不会抵消玩家决定。

## 阶段 9：试玩、测量与迭代

### 目标

判断核心概念应继续、收窄还是调整。

### 观测指标

- 首次理解采矿、胜负目标和角色分工所需时间；
- 手动与委托完成同一任务的操作次数和失败率；
- 玩家接管、归队、取消和修正 Agent 的频率；
- 玩家能否预测 Agent 下一步；
- 因看不懂或不信任而发生的无效接管；
- 一局中高层委托与传统微操的使用比例；
- 是否愿意尝试另一种扩张或进攻方式再玩一局。

### 退出条件

试玩结果证明 AI 下属减少重复操作、保留关键决策和微操乐趣，并让玩家感到能够驾驭更大的战场；否则优先修改任务透明度和控制权，不扩充内容。

## 首要风险

1. **委托需要频繁纠正**：缩小 Agent 自主范围，强化模板和受阻反馈。
2. **行动正确但难以理解**：加强地图路线、阶段、理由和条件显示。
3. **自动化削弱参与感**：Agent 只处理执行，战略方向和关键局部留给玩家。
4. **玩家与 Agent 抢控制**：使用明确状态与人工归队，不采用隐式超时。
5. **Godot 节点泄漏为权威状态**：核心规则只存在于 `SimulationWorld`，节点只消费快照和事件。
6. **UI 与 Agent 命令路径分叉**：两者必须复用相同 `GameCommand` 和 `CommandValidator` 测试。
7. **导航和编队在狭窄区域阻塞**：先测量 A*、slots 和纵队降级，再按触发条件升级。
8. **引擎版本漂移**：锁定精确 patch，版本升级独立提交并完整回归。
9. **未验证依赖和过早复杂化**：GUT 先 spike，不提前引入 LFS、流场、ECS 或多套导航。
