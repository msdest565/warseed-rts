# WARSEED 低成本开发手册

> 当前性能政策：D-028（2026-09-16，Accepted）暂缓性能通过要求，优先完成整体逻辑；下文历史性能门仅作参考。功能、确定性、公平知识、存档、UI与导出仍须验证。

本手册规定开发代理如何分工和交接；[实时状态](AI_DEVELOPMENT_STATE.md)仍是任务状态唯一来源，[主工作流](AI_DEVELOPMENT_WORKFLOW.md)仍决定工程门。开发代理与游戏中的将领 Agent 是两种角色；外部模型不能成为游戏运行依赖。

## 1. 最短接手路径

1. 先读根目录 `AGENTS.md`，再读状态文件第1节控制块、第11节接手清单及最新维护记录。只有出现契约冲突才追溯历史段落，避免每次载入数万字历史。
2. 首次进入仓库读主工作流；同一上下文内未变化不重读。仅在使用 `/goal` 时读命令协议。
3. 找到当前工作项，读取其 `source_documents` 的相关章节，再用 `rg` 定位符号和测试。依赖未满足或存在 `USER_PAUSE` 时，不领取实现任务。
4. 执行 `git status --short`、`git diff --check`、`git rev-parse HEAD`；记录已有改动与本任务允许修改范围。
5. 使用[委派模板](AI_DELEGATION_TEMPLATE.md)冻结一个可验收切片。普通代理可直接接手；只有预计节省的实现工作大于打包、审查和返工成本时才委派。

当前起点索引（2026-09-16，具体状态仍须回读控制块）：R3与R4-001/002/003完成；R4-004已有实现且用户已恢复R4/R5，不能从零重做；09-14维护包已交付。实时验证进度以状态第22节为准。

## 2. 分工与审查强度

| 等级 | 适合任务 | 实施者 | 主代理验收 |
|---|---|---|---|
| L0 | 链接修复、已确定文案翻译、证据表整理、只读查找 | 本地脚本优先，其次低成本模型 | 读全部小diff，核对来源和机械检查；不重写整份答案 |
| L1 | 已冻结契约的纯展示逻辑、小范围测试补充、既有typed数据样板 | 经小任务验证的低成本模型 | 读全部diff，复核关键边界和所需测试证据 |
| L2 | 命令/队列、战斗、经济、导航、存档、知识隔离、跨系统接口 | 主代理定契约并审查核心；可委派只读调查或独立测试准备 | 必须审查完整行为链、拒绝/时序/隔离；运行对应完整门 |
| L3 | 产品取舍、阶段出口、取消约束、大规模迁移 | 主代理整理证据，产品负责人作需要的决定 | 不以低成本输出或“测试绿了”替代决定 |

文件少不代表风险低：一行 tick 顺序、冷却来源或存档默认值也按 L2。UI 直接读写世界、测试更新黄金或降低断言均升级。低成本模型的接口可用不等于代码能力通过认证；首次每种任务类型做一个可独立核验的小样本，不批量试遍所有模型。

默认一个实施者、一个最终审查者。需要并行时，只并行独立只读调查；共享目录只允许一个写入者，真实键鼠测试只能串行。只有用户或适用规则允许才使用子代理；本用户已授权为降低成本合理委派。不要复制整段对话给每个子代理。

## 3. 控制上下文与调用成本

- 委派输入只包含目标、当前行为、验收、允许文件、必要接口/代码片段、基线和禁止事项。长文件给符号名与相关片段，缺口由实施者一次性列出。
- 工作包建议1–5个实现文件、一个行为目标；超过约300行行为diff或跨两个权威模块时重新评估拆分。它们是分工提示，不是允许漏读或拆散必要纵向切片的硬限制。
- 默认一次实施、一次带具体失败证据的返工；第二次仍失败交由主代理定位，禁止用相同提示无限重试。401/403、额度不足或路由失败先停止；超时可能已计费，不自动重发。
- 先给出文件/符号定位，再读需要内容。日志落在 `artifacts/`，正常只返回命令、退出码、摘要和错误附近上下文。主代理按需复查原始证据。
- 固定契约内容保持稳定，追加新失败信息；是否命中服务缓存以usage为准。新代理没有上下文时重新提供最小契约，不能只说“按之前做”。
- 每包记录请求模型、实际返回信息、输入/输出token、尝试次数、耗时、验收结果和拒收原因。服务未报usage则UNKNOWN；未核实币种、组倍率、缓存/推理计费前费用UNKNOWN，不声称节约百分比。
- 比较总成本：实施调用 + 返工调用 + 主代理审查 + 测试等待期间的无效交互。连续三个已接受样本后再决定扩大该模型的任务范围。
- `max_tokens` 是一次API调用的输出限制；不等同 `/goal budget`，也不保证货币硬上限。仅用户明确指定时设置目标token预算。

## 4. 交付与验收协议

接任务时记录 `base_commit`、`git status`、允许文件及读取时SHA-256。交付包含变更动机、diff、逐条验收结果、日志和受验文件哈希；只能写实际运行的命令，不能把建议测试写成PASS。

主代理按顺序验收：

1. 检查基线是否改变、是否碰到用户已有改动、是否越过允许文件。过期补丁先重新对齐上下文，禁止强行覆盖。
2. 阅读diff；低风险关注内容正确与范围，高风险检查从输入到命令/校验/应用/快照/消费者的完整链。
3. 对照验收条件，检查原始日志的结束标记、退出码、脚本错误和测试范围。外部文本模型没有执行环境，其“PASS”只是主张，必须本地执行。
4. 如果独立执行者已在同一源码、环境和命令上完成验证，核对日志和哈希即可复用，不必主代理再跑一遍。最终完整门本身包含18套时，不紧邻再重复同一18套。
5. 受验源码、内容、测试、运行环境或命令参数变化会使相关证据失效；文档改字不使战斗证据失效。基线本来失败须单独记载。相同提交但工作区不同，不算同一受验源码。
6. `git diff --check`，更新工作项与实时状态。只由主代理决定DONE和Git交接；当前会话明确授权过的提交/推送无需再次询问，但任务外不得擅自发布或创建PR。

拒收条件：未解释的黄金漂移、禁用断言、隐藏真值读取、自由字典替代typed契约、存档失败回空档、UI写权威状态、仅入队即声称执行、越权抢手控、伪造日志。返工时给出具体文件/失败输入/预期值；不要求重写无关部分。

## 5. 验证如何省钱

完整矩阵在主工作流第10节；这里给实际入口，不复制另一份门禁。

| 变更 | 首先运行 | 扩大验证的条件 |
|---|---|---|
| 文档/开发工具 | 链接与结构、工具离线测试、diff检查 | 不改游戏，无需Godot发布门 |
| 手控战斗 | `tests/tools/manual_battle_smoke.gd` | 战斗/命令变化运行18套、四关、实渲和完整门 |
| 将领任务图 | `tests/tools/commander_task_graph_smoke.gd` | 权威变化加执行审计、隔离/同tick、完整门 |
| UI/本地化 | 相关集成测试 | 中英五档 `tests/tools/accessibility_resolution_matrix.gd`，真实键鼠串行 |
| 存档 | `tests/tools/composition_persistence_smoke.gd` | 旧档/坏档/原子恢复、隔离档链式和完整门 |

Godot版本为4.6.3 stable mono。可执行路径从本机配置获取；不要把开发机绝对路径写入游戏。示例环境变量由操作者设置，未设置时先定位安装：

```powershell
& $env:WARSEED_GODOT_CONSOLE --headless --path . --script res://tests/tools/commander_task_graph_smoke.gd
& $env:WARSEED_GODOT_CONSOLE --headless --path . --script res://tests/test_runner.gd
powershell -ExecutionPolicy Bypass -File tools/verify_grey_ridge_release.ps1 -GodotConsolePath $env:WARSEED_GODOT_CONSOLE
```

真实测试套数由 `tests/test_runner.gd` 决定，当前18套。失败先修复再扩大，不为抽到PASS反复执行。共享权威状态、命令、地图、存档或阶段出口改变时完整发布门仍必需；低成本分工不能减掉这些门。

D-028已将性能暂缓扩展至当前后续开发和阶段出口；完整发布脚本默认跳过性能门并明确记录DEFERRED。未来恢复要求后才显式传入 -EnforcePerformance。`SIMULATED`与可选`HUMAN / NOT_RUN`始终区分。
