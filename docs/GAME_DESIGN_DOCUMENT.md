# WARSEED 游戏企划书

> 文档状态：完整 MVP 产品规格

> 更新日期：2026-08-18

## 1. 产品概述

### 1.1 一句话定义

《WARSEED》是一款以常驻军团卡牌组织约百个战场实体、由性格明确的将领 Agent 自主执行、玩家在战略意图与编队级直接指挥之间切换的即时战术游戏。

### 1.2 玩家幻想

玩家不是逐个士兵点射的操作者，也不是观看自动战斗的旁观者。玩家扮演最高指挥官：在战前用将领卡、部队卡和战法卡组成军团；在战中争夺资源区、部署预备队、改变目标与姿态；在决定性局部，直接选中一张部队卡，为整个真实编队绘制路线和展开阵线。

玩家的核心感受应当是：

> 我决定把谁交给谁、在哪里打、以什么方式打；将领负责把意图变成可信的战场行动；必要时，我能接过一支完整编队亲自完成关键机动。

### 1.3 类型与形态

| 项目 | 定义 |
|---|---|
| 核心类型 | 2D 俯视角即时战术 / 轻量 RTS |
| 核心单位规模 | 每方约 5—9 张部队卡，展开为约 60—120 个实体 |
| 核心操作粒度 | 军团、将领所属部曲、单张部队卡；不逐个士兵微操 |
| 单局时长 | 首个切片 5—8 分钟；正式会战目标 15—25 分钟 |
| 核心输入 | 地图拖放、姿态切换、战法装配、编队路线与阵线绘制 |
| 随机性 | 不抽牌、不洗牌；战斗模拟可有受控随机，但敌方不得因玩家选择临时改答案 |
| 核心平台 | Windows，键鼠优先 |

### 1.4 目标玩家

- 喜欢《全面战争》的将领与部曲关系，但不想同时微操大量独立单位的玩家；
- 喜欢《钢铁雄心》的意图、组织和战线感，但希望局部战斗更直接可见的玩家；
- 喜欢经典 RTS 的侦察、资源争夺和克制，但不想被采矿车与高频生产操作占满注意力的玩家；
- 对可解释 AI、持续部队和战后故事感兴趣的单机策略玩家。

## 2. 核心设计支柱

### 2.1 卡牌就是军队，不是技能皮肤

每张将领卡和部队卡都对应持续存在的组织。卡面上的人员、装备、损失、经历和隶属关系会在战场上展开为真实实体，并在战后回写。移除卡牌系统，就会同时失去编成、战法槽、持续成长、预备队投入和直接控制入口，因此它是核心系统而非 UI 包装。

### 2.2 Agent 执行意图，而不是替玩家决定战争

玩家决定目标、优先级、风险和资源投入。将领 Agent 根据性格、情报、战法和下属能力，自主完成行军、展开、接敌、追击、脱离与报告。Agent 必须使用与玩家相同的合法命令和阵营情报，不能直接修改战果或读取战争迷雾后的真值。

### 2.3 两种指挥粒度无缝共存

- 粗粒度：把将领卡拖到战区，让其组织全部部曲完成意图；
- 中粒度：修改将领目标、姿态、路线偏好、撤退阈值或增援；
- 细粒度：选中一张部队卡，为整个编队绘制路线、朝向和展开阵线。

细粒度的下限是完整编队，不是单兵或单车。玩家直接命令优先于 Agent，但没有隐式超时抢回。玩家按 R、点击交还按钮，或下发新的将领执行决策、路线、姿态，均表示明确交还相应部队；后台 Agent 更新不能自行解除接管。

### 2.4 情报不完整，但结论必须有来源

侦察报告必须标注来源、时间和可信度。未侦察区域不是安全区域；失去视野的敌军只保留最后确认位置和衰减中的估计。主 AI 可以汇总矛盾情报、指出风险，但不输出一个伪装成唯一正确答案的“最优解”。

### 2.5 敌方计划固定、反应有边界

关卡开始时，敌方初始编成、计划、触发条件和反应规则已由场景数据与随机种子锁定。敌人可以按照事先定义的规则对已观察到的行动作出反应，但不能在读取玩家选择后临时生成针对性答案。复盘应能解释敌人为什么改变计划。

### 2.6 地形、兵种和时间共同制造选择

兵种没有脱离地形的绝对强弱：装甲在开阔地形成正面优势，突击单位在废墟和据点近战强，火力单位依赖视野与掩护，侦察单位负责发现与脱离。资源结算、部署时间、行军时间和支援冷却共同构成机会成本。

## 3. 卡牌系统

### 3.1 卡牌的共同规则

- 全部己方卡牌始终可见，不存在牌库、抽牌、弃牌或随机手牌；
- 卡牌是持久对象，拥有稳定 ID，战场损失和成长回写到同一对象；
- “挂载”表示稳定的组织关系，不表示消费卡牌；
- 卡牌进入冷却、受损、失联或预备状态时仍保留在军团板上，只改变状态；
- 战场实体被消灭不等于卡牌立即消失：卡牌先记录损失，是否解散由战后规则决定。

### 3.2 将领卡

将领卡代表一个持续存在的指挥 Agent，包含：

| 字段 | 作用 |
|---|---|
| 指挥容量 | 限制可统辖的部队规模或组织成本 |
| 性格 | 决定如何解释模糊命令和承受风险 |
| 特长 | 影响搜索、展开、识别、协同等行为能力 |
| 战法槽 | 限制同时装配的作战方式 |
| 当前任务 | 显示目标、阶段、计划路线和预计接敌时间 |
| 状态 | 正常、受阻、交战、撤退、失联、等待增援 |

示例：

```text
┌────────────────────────┐
│ 白久漾｜侦察将领        │
│ 指挥容量：3             │
│ 谨慎：不主动进入劣势战斗 │
│ 特长：隐蔽、识别、脱离   │
│ 战法槽：[隐蔽搜索][空槽] │
└────────────────────────┘
```

性格不是简单数值加成。例如同样收到“监视中央”的命令，谨慎将领会保持撤离路线并优先报告，果断将领可能主动逼近以提高识别精度。

### 3.3 部队卡

一张部队卡代表一个真实、持续、可展开的编队，是战场上最低可直接指挥单位。

```text
[高速侦察连] 18 人
[无人机中队] 12 机
[装甲突击营] 30 人
[工程支援连] 10 人
[远程火力群] 16 门
[防空分队] 6 车
[总部装甲预备队] 8 车
```

卡面至少显示：编制与现员、核心装备、士气/组织、弹药或支援状态、当前位置、当前命令、所属将领、关键战损和可用战法。战场上约百个实体可以被玩家通过约七张部队卡管理。

部队卡的组织形式：

```text
[白久漾]
 ├─ [高速侦察连]
 └─ [无人机中队]

[涤天]
 ├─ [装甲突击营]
 └─ [工程支援连]

[林默]
 ├─ [远程火力群]
 └─ [防空分队]

[总部]
 └─ [装甲预备队]
```

### 3.4 战法卡

战法卡是装配给将领的持续作战方式，不是点击后立即造成效果的技能。

首批战法候选：

| 战法 | 行为变化 | 主要代价 |
|---|---|---|
| 隐蔽搜索 | 降低暴露，分段建立观察点 | 推进更慢、覆盖面较窄 |
| 三三编组 | 小组互相支援，降低局部失控 | 展开时间增加 |
| 佯攻牵制 | 制造进攻表象并避免深追 | 对明确突破目标效率低 |
| 交替掩护 | 一部移动、一部掩护 | 行军速度降低 |
| 炮火准备 | 等待视野与火力就绪后推进 | 暴露意图、消耗时间 |
| 集中突破 | 在窄正面投入优势兵力 | 侧翼与其他方向变弱 |
| 弹性防御 | 遇强敌后退至下一支撑点 | 可能主动放弃地面 |
| 遭遇后脱离 | 首次接敌后优先保存情报 | 无法稳定守点 |

战法改变 Agent 的决策树和执行约束，而不是直接修改攻击力。例如：

```text
[涤天] + [装甲突击营] + [佯攻牵制] -> 中央城镇
```

其含义是涤天带队推进、展开、接敌并制造主攻假象，同时按照性格与战法处理局部风险。

### 3.5 荣誉与装备卡

荣誉与装备卡在战后挂载到经历过战斗的部队上，用来形成长期差异。每项收益必须附带成本、限制或组织影响。

| 示例 | 收益 | 代价 |
|---|---|---|
| 集体嘉奖 | 部队晋升精锐，执行复杂命令更稳定 | 部署与补充成本提高 |
| 老练无人机操作组 | 目标确认更快 | 侦察覆盖范围降低 |
| 野战维修组 | 战斗间隙可恢复轻度装备损伤 | 行军和部署速度下降 |
| 临时补充兵 | 快速恢复现员 | 士气上限与协同下降 |

### 3.6 总部预备编制与支援指令

《灰脊矿区》灰盒中的“当前手牌”不再使用这个名称，改为两个始终可见的区域：

- **总部预备编制**：尚未投入战场的部队卡，例如“装甲矛头”“雷鸣火力群”；支付补给并等待部署时间后进入战场，之后持续存在；
- **支援指令栏**：空中侦察、紧急筑垒等战区能力。它们是有费用、冷却和合法目标的指令，不参与抽牌，也不伪装成军队卡。

这样既保留第一段灰盒中的部署决策，又不破坏“卡牌是持续军队与打法”的核心定义。

## 4. 军团编成与持续成长

### 4.1 战前编成

战前阶段完成四件事：

1. 选择参与会战的将领；
2. 把部队卡挂到将领下，满足指挥容量与兵种限制；
3. 为将领装配少量战法；
4. 决定哪些部队首发、哪些留在总部预备队。

《灰脊矿区》的首切片固定提供三名将领和四张部队卡，玩家必须为每张部队卡指定所属将领，为每名将领选择一张合法战法和一种初始姿态，并准确选择两张首发卡。界面持续显示已用/可用指挥容量；任何超容量、非法隶属、非法战法或首发数量错误都会阻止会战开始，并给出结构化原因。战前阶段权威时间保持在 tick 0，战场命令不能修改预览世界；只有合法 `ArmyPlan` 提交后，系统才据此创建真实首发编队并启动八分钟计时。

编成的核心取舍不是堆叠攻击力，而是建立执行能力。例如火力群挂给谨慎将领会更重视安全射界，挂给激进将领可能更早前推；工程支援连放入装甲军团能提高持续推进能力，却占用一部分指挥容量。

### 4.2 战损与补充

- 战场上的实体损失实时反映到部队卡；
- 撤出战场的残部保留经历和伤员状态；
- 补充需要资源、时间和人员来源，不自动回满；
- 同一部队反复遭受重创会积累组织问题；
- 全灭部队是否保留番号、重建或永久解散，由战役规则和玩家决定。

### 4.3 成长目标

长期成长应让玩家记住“哪支部队做过什么”，而不是只追求稀有度。成长来源包括：完成艰难任务、在不利条件下成功脱离、准确侦察、掩护友军撤退、守住关键据点和保存核心骨干。

## 5. 会战核心循环

### 5.1 单局循环

```text
读取任务与地形
  -> 编成军团并装配战法
  -> 首发部署与侦察
  -> 争夺资源区 / 支援节点
  -> 收到带来源和置信度的敌情
  -> 调整将领目标、姿态和增援
  -> Agent 自主展开与交战
  -> 必要时直接控制一张部队卡
  -> 扩大战果或保存战力
  -> 摧毁敌方总部 / 达成关卡目标
  -> 战损、荣誉和经历回写
```

### 5.2 战中资源

首要会战模式使用“补给”，而不是矿车往返采矿：

- 基础收入按固定周期获得；
- 占领资源区后按区域周期自动产出；
- 补给用于投入预备部队、请求支援和战场工程；
- 资源区不需要矿车，也不增加额外占领进度条；
- 区域控制由范围内有组织战力、敌我争夺状态和短暂稳固时间共同判定。

该设计把玩家注意力留给军团部署和战场判断。基地建造、矿车采集和逐单位生产不属于首个会战核心，可保留为未来独立模式或战役层能力，但不应阻塞核心验证。

### 5.3 人口与部署

人口表示本场可维持的战场实体上限。预备部队投入需要满足：补给足够、人口未超限、部署区可用、部署时间完成。部署不是瞬间召唤；敌人可以观察到部分征兆，但不能凭未获得的情报知道具体编成。

### 5.4 胜负与节奏

- 标准胜利：摧毁敌方总部或完成场景特定目标；
- 标准失败：己方总部被摧毁；
- 同一权威 tick 双方总部均被摧毁时，默认双方失败/平局，由模式规格明确；
- 首个灰盒要求八分钟内结束，以验证信息、部署和指挥循环是否足够紧凑；
- 地图应每 20—40 秒产生一次需要理解但不一定立即操作的新状态。

## 6. 战场规则

### 6.1 基础兵种与地形克制

| 战团 | 优势 | 弱点 | 理想地形 | 典型任务 |
|---|---|---|---|---|
| 装甲战团 | 开阔地正面战斗、突破和追击 | 废墟展开差、易被伏击 | 开阔地、宽路 | 突破、夺点、机动预备 |
| 突击战团 | 近距离、掩体与据点战 | 开阔地接敌损失大 | 城镇废墟、据点 | 清剿、固守、巷战 |
| 火力战团 | 远程压制、区域拒止 | 被接近后脆弱、依赖视野 | 后方高地、开阔射界 | 压制、准备、反集结 |
| 侦察战团 | 发现、识别、规避和报告 | 不能正面守点 | 高地、林缘、侧翼 | 搜索、监视、诱导 |
| 工程支援 | 构筑、维修、开辟通路 | 独立战斗弱 | 据点、交通线 | 筑垒、抢修、支援 |
| 防空分队 | 保护军团免受空中支援 | 对地输出有限 | 随主力机动 | 区域防空、护卫 |

克制应主要通过射界、接敌距离、掩体、展开速度、侦察确认和组织状态实现，避免只做隐藏的百分比伤害加成。

### 6.2 姿态

每名将领和每张被直接控制的部队卡至少支持：

| 姿态 | 行为重点 |
|---|---|
| 谨慎 | 保存战力，避免进入估算劣势，缩短追击 |
| 均衡 | 按战法与默认阈值执行 |
| 强攻 | 接受更高损失换取时间和地面，扩大追击 |
| 固守 | 停止主动推进，围绕区域建立防御 |
| 脱离 | 优先断开接触并前往安全集结点 |

姿态不能绕过将领性格。例如谨慎将领在“强攻”下会提高风险上限，但仍不会执行明显自杀式冲锋；若玩家需要更精确的强制路线，应直接控制具体部队卡。

### 6.3 视野与报告

情报条目至少包含：

```text
目标类别 / 估计数量 / 位置或区域
观测来源 / 观测时间 / 可信度
移动方向 / 预计到达时间
是否仍在持续观测
```

主 AI“枢机”负责合并重复报告、标记矛盾和计算距离，但不得把估计伪装成事实。玩家可以点击报告，在地图上查看观测范围、最后确认位置和可能路径。

### 6.4 Agent 局部执行

将领 Agent 的最小闭环为：

```text
解释意图 -> 检查情报和下属 -> 选择路线与展开点
-> 行军 -> 建立接敌队形 -> 交战/规避
-> 根据性格、战法和阈值调整 -> 报告结果
```

玩家应能看到：当前意图、执行阶段、参与部队、预计时间、风险、改令原因和受阻原因。Agent 失败必须能归因于情报错误、路径不可达、兵力不足、关键部队被接管、资源不足或触发的撤退条件。

## 7. 操作与界面

### 7.1 屏幕结构

当前卡牌会战采用以下布局（2026-09-10 战术规划维护）：

```text
┌──────────────┬──────────────────────────────┬────────────────┐
│ 战区支援      │          战场地图             │ 最终目标 / 途经区│
│               │ 空格战术暂停、Esc 设置         │ 姿态 / 预备意图  │
│ 小地图        │                              │ 可滚动决策列表   │
│               ├──────────────────────────────┤ 本局历史         │
│               │ 将领汇总 → 各下属部队卡兵力    │                 │
└──────────────┴──────────────────────────────┴────────────────┘
```

底部军团卡牌按将领分组，每张部队卡显示现员/编制，预备卡显示可用兵力，手控与归队卡有短文本标记。将领汇总下属兵力、固有风格和可调整姿态，并用绿色“空闲”、黄色“执行”、红色“交战”表达当前状态；红色只依据合法可见接触或本方交战状态。军团板按将领和卡数计算高度、在列宽足够时展开卡片网格，当前最多十二卡直接展示，不依赖军团区滚动。窄屏仍保留右侧决策，支援和小地图置于左侧地图下方，军团板占底部整行。军团标题右侧有 R 交还按钮；直接控制部队时地图左上提醒交还入口。

最终目标决定到达或争夺的区域；途经区仅改变接近路线，选择“直接前往目标”或与目标相同则不增加途经点。姿态、固有风格与预备意图的说明在持续悬停 0.5 秒后显示进度条，再经过 0.5 秒显示文本。当前预备策略记录意图，具体预备卡仍由玩家在决策区投入，自动消费策略按 R4 工作项实现。

空格战术暂停只冻结战场推进：移动、战斗、收入、冷却和 Agent 不推进，界面、说明、选择、路线规划与命令提交仍可用。命令按统一校验管线排队，恢复后按原顺序执行，不补跑暂停时间。Esc 设置菜单保留独立菜单暂停语义，关闭菜单后保持原战术暂停状态。新会战与重开清除战术暂停。

左侧支援入口独立显示“冷却：N 秒”或“冷却：就绪”；剩余时间按权威 tick 向上取整，战术暂停时冻结。一次性工程开路显示“无冷却”。冷却中的上下文入口仍可查看右侧目标与拒绝原因，执行继续经过统一校验。

### 7.2 粗粒度操作

- 拖动将领卡到地图区域：为整个军团下达意图；
- 在地图上拖动将领任务箭头：修改主路线或目标优先级；
- 切换将领姿态：改变后续执行边界；
- 把部队卡从总部预备区拖给将领：正式投入增援，短时间不能撤销；
- 把战法卡挂入将领槽：在允许的准备窗口后改变执行方式。

### 7.3 细粒度操作

- 点击部队卡：选中该编队和其全部真实实体；
- 在地图上绘制路线：指定编队机动路径；
- 拖出阵线并调整朝向：指定展开位置和正面；
- 指定目标或防区：覆盖该编队当前 Agent 子命令；
- 按 R 或点击交还：优先归还所选整卡，选择将领时交还其手控部队，未选择部队或将领时交还全部手控卡。有效旧任务沿用归队过程；无旧任务或旧任务已终止时交给当前将领执行现有目标，无活动意图则原地受命，不复活已取消任务。单位不能瞬移。
- 下发新的将领执行决策、路线或姿态：同一条验证通过的玩家命令先交还该将领部队，再建立新任务；拒绝命令不改变控制，其他将领的手控部队不受影响。暂停时只排队，恢复推进后才确认生效。

不提供框选单个士兵、逐车拉扯或单体集火作为常规玩法。个体层行为由部队 Agent 和确定性安全规则处理。

### 7.4 反馈要求

- 改令立即显示接收者、预计生效时间和受影响部队；
- 将领自主改令必须显示原因；
- 卡面现员与地图存活实体一致；
- 敌情的“可见、最后确认、推测”使用不同视觉语言；
- 路线、阵线、目标、姿态和撤退阈值可在一到两次交互内检查；
- 不使用频繁弹窗打断实时决策。

## 8. 样板关卡：《灰脊矿区》

### 8.1 验证目的

《灰脊矿区》是第一局文字灰盒和首个可玩垂直切片，用来验证：

1. 玩家能否在 30 秒内理解胜负、资源区和军团板；
2. 常驻卡牌是否比随机手牌更自然地表达军队；
3. 玩家能否根据不完整情报在集中优势与多线行动间取舍；
4. 将领 Agent 是否能把意图转成可解释的局部战斗；
5. 玩家是否会在关键时刻直接控制一张部队卡，而不是退回单兵微操；
6. 固定敌方计划是否支持复盘，而不让玩家感到系统在临时针对自己。

### 8.2 地图

```text

       西部矿场 ------ 中央中继站 ------ 东部补给站
       开阔地             城镇废墟          林地

                         支援冷却加快
                           |

```

每个资源区每 30 秒结算一次。占领后自动产出，不需要矿车。

### 8.3 胜负目标

- 八分钟内摧毁敌方总部；
- 己方总部被摧毁即失败；
- 双方总部在同一权威 tick 被摧毁，判定双方失败；
- 暂停不推进权威时间。

### 8.5 初始情报

- 游隼直接光学观测：约 12 名敌方突击单位正在进入中央废墟，预计 25 秒后抵达中继站，可信度高；
- 西部声学传感器：8 秒前捕捉到履带引擎，估计 1—3 辆未知载具正向西部矿场移动，可信度中等；
- 东部林地：未侦察，无可靠情报，不能视为安全。

权威真值中，第二条报告对应一支真实存在的 2 辆装甲先遣 formation；正常玩家快照只保留 1—3 辆的声学估计，不泄露精确编制、目标或计划 ID。

|---|---:|

### 8.6 第一条命令的表达方式

玩家不从 A/B/C 菜单中选择剧情分支。A、B、C 只作为灰盒测试中的常见方案，正式交互由军团板和地图自由组合：

- 把“雷鸣火力群”从总部预备区拖给中央方向的将领；
- 把涤天拖到中央废墟，选择均衡或强攻姿态；
- 把白久漾的目标改为西部矿场；
- 或投入“装甲矛头”、请求空中侦察、改变任意一支部队的阵线。

系统必须接受一句结构化的自定义命令组合，而不能只识别预写选项。

### 8.7 敌方锁定规则

关卡数据必须在开局时锁定：初始部队、首要目标、预备队、可观察触发器、反应延迟、撤退阈值和支援预算。敌方只能对已经进入其阵营知识的事件作出反应。开发调试层需记录每次改令的触发条件，复盘可验证同一初态、种子和玩家命令序列得到相同关键结果。

首切片按既有战役局数确定性轮换三套计划：

- “中央突击”：12 人主力进入中央，2 辆先遣前往西部；
- “西线钩击”：主力经中央转向西部，先遣在中央屏护；
- “西部佯攻”：主力进入中央，先遣先向西部投入固定承诺时间，再在预先锁定的 tick 转向中央。

计划开始和时间表转向分别以 `LOCKED_OPENING_PLAN`、`LOCKED_PLAN_TIMELINE` 记录；针对玩家接触的反应只能以 `LEGAL_FACTION_OBSERVATION` 记录。侧翼拦截优先交给先遣，总部威胁由距离目标最近的存活敌方编队处理，中央反击和主力损失撤退仍由主力承担。正式玩家 UI 不显示计划真值或反应表。

## 9. 战役与局外循环

首个切片不需要完整战役，但长期产品应形成：

```text
选择会战 -> 阅读任务与情报 -> 编成军团
-> 会战 -> 统计战损与表现 -> 补充/整编
-> 授予荣誉与装备 -> 将领和部队形成新关系 -> 下一场会战
```

战役层提供资源和人员约束，但不能退化为稀有度抽卡。新将领、部队、战法和装备应通过剧情、军备、战功、俘获或组织重建获得。

### 10.1 首发内容目标（概念阶段）

| 内容 | 首个切片 | 完整 MVP |

| 会战地图 | 1 | 3—5 |
| 可用将领 | 3 | 5—7 |

| 战法卡 | 4 | 10—16 |

| 单局实体规模 | 40—70 | 80—120 |

以上是范围控制目标，不是最终商业内容承诺。

### 10.2 教学顺序

1. 只拖动将领卡下达目标；
2. 认识姿态与情报可信度；
3. 投入总部预备部队；
4. 直接选择一张部队卡绘制阵线；
5. 明确归还 Agent；
6. 战后处理损失和荣誉。

### 10.3 首发会战梯度

完整 MVP 以四场可重玩的会战构成教学和内容梯度。每场会战至少拥有三套在读取玩家行动前锁定的敌方计划；同一套规则允许不同军团编成、主攻方向和战损结果，而不是用临时反制制造伪重玩性。

| 顺序 | 会战 | 主要地形 | 新增决策 | 教学职责 | 内容验收 |
|---|---|---|---|---|---|
| 01 | 灰脊矿区 | 开阔矿场、城镇废墟、林地 | 三向争夺、预备队、空中侦察 | 完成六步基础指挥教程 | 首次有效将领命令不超过 45 秒，能完成整卡接管与归还 |
| 02 | 断桥回声 | 河谷、桥梁、制高点 | 瓶颈、交叉火力、工程通路 | 教会路线、阵线正面与火力视野 | 玩家能解释一次因地形产生的胜负变化 |
| 03 | 雾林输线 | 大片林地、道路、前线补给节点 | 情报衰减、护送、分队警戒 | 教会旧情报、侦察循环与补给取舍 | 玩家不会把最后确认标记当作实时目标 |
| 04 | 黑井反击 | 工业区、纵深阵地、多个部署区 | 多将领协同、伤亡保存、有限撤出 | 教会增援条件与战后整编 | 第一局战损会影响下一局，并产生可解释的整编选择 |

会战 02《断桥回声》的工程切片已实现：损坏渡口由已部署工程卡支付补给后打开，修改敌我共用的权威网格；高地为火力单位提供可测的射程与视野收益，桥面则带来移动和防护代价；三种编成与四类策略已经进入 4×3 确定性矩阵。会战 03《雾林输线》的工程切片也已实现：旧接触会淡出并过期，最后确认点不能锁定隐藏目标；真实运输单位抵达前线节点后激活补给，敌方只能依据自己的可见接触延迟拦截。会战 04《黑井反击》的工程切片现已实现：它以卡牌级组织度、共享军团记录、有限撤出和多将领增援作为新问题，而不是单纯增加敌军数量。新地图不能只是更换障碍物布局；每张地图必须引入一个新的战略问题、一个新的情报问题和至少一个可由不同兵种解决的空间关系。

#### 10.3.1 《黑井反击》规则概要

《黑井反击》发生在 `7168×4608` 的纵深工业区。西部焦渣铁路允许装甲快速形成反击轴，中央黑井设施提供组织恢复，东部泵站高地支撑远程火力，南部撤出走廊用于保存残部。撤出不是免费的失败规避：一张卡只有全部可行动成员进入走廊后才完成撤出，本局不能再次投入，也不再争夺资源或保护总部。

组织度属于部队卡而不是单兵属性，范围为 `0—100`。它由已知的伤害、失能、接敌和恢复事件更新，Agent 与玩家看到同一快照。组织度不直接增加或减少武器伤害，而是改变将领是否继续推进、何时请求后备支援、何时转入战斗撤退，以及任务预计完成风险。这样可以表现“仍有兵力但已经无法执行复杂意图”，同时避免引入不可解释的随机士气检定。

四场会战共享一份按稳定卡牌 ID 合并的军团记录。未出现在当前内容包中的卡牌保留在记录中但不生成战场实体；同一卡牌再次出现时继承现员、累计战损、组织状态、荣誉和装备。完全重开必须先创建可恢复归档，再清空共享成长。旧版分会战记录采用保守迁移：现员取最低、累计战损取最高、已有成长不被覆盖。

四关连续性必须通过真实输入而不是直接写存档验证：从作战区选择会战、在战前关闭或启用本关教程、开始会战、下达将领意图、进入结算、滚动到具体部队卡执行成长或补员，再返回作战区进入下一关。测试运行只能在显式命名的隔离会话中启用持久化；结算行必须携带稳定卡牌 ID，不能依赖字典或快照数组的显示顺序推断操作目标。当前两轮完整串联已证明失败结算、补员、成长和黑井继承闭环，但固定输入四关均失败，不得据此宣称会战平衡完成。

《黑井反击》的专属引导不重复首局按钮说明，而是让玩家完成一次双将领分轴、观察一次合法增援判断、主动撤出一张残部卡、在结算中选择带代价的成长，并返回作战区确认同一卡牌的继承状态。自动化只证明流程与规则；“玩家是否理解保存残部比本局多占一个点更重要”仍由陌生玩家试玩门判断。

《断桥回声》的专属战法必须改变 Agent 执行，而不是只改变卡面说明。装备“快速架桥”的将领只有在玩家把进攻轴指向与工程渡口关联的区域后，才会让已部署工程卡通过同一支援命令、补给校验和共享导航网格自动开路；工程卡保持在突击部队后方。装备“高地监视”的将领会让火力卡在目标后方建立阵位，并用 30 tick 准备时间换取更稳定的远程覆盖。玩家仍决定方向、路线和编成，战法负责解释这些意图怎样被执行。

### 10.4 内容包结构

内容以可独立验证的数据包组织，而不是继续把关卡常量堆入 `SimulationWorld`。一个会战内容包至少包含：

- 场景元数据：ID、名称、时限、胜负条件、推荐规模和教学阶段；
- 地图定义：逻辑网格、战略区、部署区、地形标签、视野遮挡与支援节点；
- 双方军团表：将领、部队卡、首发/预备状态、补给与人口；
- 敌方计划集：固定开局计划、时间表、合法观测触发器、退出条件与公开复盘说明；
- 情报包：来源、时间、可信度、估计范围、矛盾关系和过期规则；
- 支援表：费用、冷却、合法目标、部署时间与反制窗口；
- 教程清单：本关引入、练习和复习的操作，不允许依赖指定唯一解；
- 验收场景：无干预、推荐方案、反常方案、失败恢复和确定性哈希。

### 10.5 完整 MVP 内容目标

| 类别 | 目标数量 | 差异要求 |
|---|---:|---|
| 会战 | 4 | 每场具有独立空间问题、情报问题和三套锁定敌方计划 |
| 将领 | 5 | 至少覆盖谨慎、稳健、果断、缜密、机会主义五类命令解释方式 |
| 部队卡 | 12 | 侦察、突击、装甲、火力、工程、防空各至少一张，另有混成与预备编制 |
| 战法 | 12 | 每项必须改变 Agent 的执行约束，并带来明确代价 |
| 支援 | 6 | 侦察、防御、补员、火力、机动、后勤各一类；均有成本和窗口 |
| 荣誉/装备 | 12 | 收益与部署、补充、速度、视野或组织成本成对出现 |
| 敌方计划 | 每场 3—4 | 开局前锁定，可通过合法情报识别，战后可解释 |

内容扩充优先增加“不同决策”，而不是增加同功能数值变体。任何新卡必须回答它改变了哪种编成关系、哪类地图问题或哪条 Agent 决策边界。

### 10.6 新手引导体系

引导由五层组成，并始终服从“地图不被遮挡、模拟真值不被绕过、玩家可以跳过和重开”的原则：

1. **战前编成提示**：在编成板内解释容量、战法、姿态和准确两张首发卡；只提示约束，不推荐唯一最优编成。
2. **首局情境教程**：固定显示在地图外侧栏，依次验证将领目标、空中侦察、预备队、整卡路线、归还 Agent 和战后复盘。步骤由已接受命令或权威快照推进，不能手动伪造完成。
3. **上下文回执**：非法目标、补给不足、路线不可达、控制权冲突等都显示权威拒绝原因，并给出下一项合法动作。
4. **可回放教范**：完成或跳过后保持一个紧凑入口；玩家可在战前重新启用，不因清空战役记录永久丢失入口。
5. **战后解释**：结算页指出战损、荣誉/装备代价、敌方已公开反应和下一局可尝试的差异，不用胜负分数替代解释。

四场会战分别保存“未开始、进行中、已完成、已跳过”状态。作战区显示所选会战的状态并提供从头重播；重播只重置该关教程，不修改持续军团、战损、成长或会战结果。一关的完成或跳过不得影响其他会战。

教程不得暂停或减速权威模拟、修改敌方锁定计划、赠送额外补给或替玩家提交命令。教程可以高亮相关 UI、展示输入提示和记录完成事件。跳过只关闭当前会战的教学显示，不改变战局。

首局教程的权威完成条件：

| 步骤 | 玩家学习目标 | 完成证据 |
|---|---|---|
| T1 | 将领卡代表可解释的指挥 Agent | 任一合法将领目标命令被接受 |
| T2 | 情报有来源、范围和时效 | 任一合法空中侦察命令被接受 |
| T3 | 预备卡是持续部队，不是一次性技能 | 任一预备部队部署命令被接受 |
| T4 | 最低直接控制粒度是完整部队卡 | 带航路点或阵线的整卡路线命令被接受 |
| T5 | 玩家控制权必须明确归还 | 对已接管部队提交合法归还命令 |
| T6 | 战损和成长跨局存在 | 战局结算生成并展示四张持续部队卡记录 |

引导验收不以“面板存在”为通过。自动测试必须证明步骤不会被拒绝命令推进、乱序操作不会丢失已完成事实、跳过不提交战场命令、语言切换可即时刷新；人工试玩必须证明教程没有覆盖地图，且玩家能在不查看外部说明的情况下完成至少 T1—T5。

### 10.7 完整 MVP 收敛边界

四关、五将领、十二部队卡、十二战法、六类支援和十二项荣誉/装备达到目标后，后续工作不再以新增内容数量衡量。完整 MVP 的最后阶段只处理七类证据：逐关教程重播、上下文回执、四关串联、分辨率与可访问性、音频和战斗可读性、平衡与性能冻结、陌生玩家理解度。

工程自测必须贯通作战区、战前编成、四场会战、结算成长和共享记录；但它只能证明流程可用和规则一致，不能证明陌生玩家理解。没有真实参与者记录时，构建标记为 MVP 候选版，不宣称完成全部产品验收。

P6.4 的显示基线固定覆盖 `1280×720`、`1920×1080`、`2560×1600`、`640×800` 与 `480×800`。地图必须保持独立且不被命令面板覆盖；滚轮只有位于地图内才控制相机；战前、暂停与结算允许纵向滚动但不得要求横向滚动；阵营、情报状态与关键反馈必须同时使用文字或形状编码，不得只依赖颜色。

P6.5 的反馈基线固定为“一个权威事件来源、三条同时声音上限、文本/视觉永不依赖音频”。单兵齐射和命中允许被限流，三源集火、整卡受压、增援、总部危机和胜负必须保留编队级提示；隐藏单位不能通过空间声源暴露精确位置。普通接触不得覆盖正在显示的交战、战损或总部警告，暂停菜单必须提供统一战斗音频开关。

P6.6 的发布冻结基线固定为“四关 × 六类玩家策略 × 三套锁定敌方计划”的 72 案例审计，并冻结军团、教程和试玩记录格式。推荐、保守、情报优先、资源贪婪与无干预用于暴露不同资源和指挥节奏，故意失败用于证明权威失败链可达；审计不能通过敌方隐藏视野、额外资源或读取未提交意图修补结果。80 实体是当前 Windows 正式性能门，120 实体保留为必须明确报告通过或失败的扩展测量，不得以“非正式”掩盖未达到 60 FPS 数值线。

## 11. AI 与公平性

### 11.1 我方 Agent

- 依据将领性格、战法、目标、姿态和阵营知识行动；
- 对命令给出接受、保留、无法执行或请求澄清等明确反馈；
- 关键行动保留“为什么”与退出条件；
- 只能控制其组织树下且未被玩家接管的部队；
- 允许下属单位执行脱困、近距自卫和规避等安全行为。

### 11.2 敌方 Agent

- 使用同一套命令、视野、路径、战斗和资源规则；
- 难度主要改变反应延迟、计划质量、风险判断、协同和误差，不授予全图视野；
- 同一场景的计划与反应表在开局锁定；
- 可使用多套预先设计的计划模板，但选择发生在读取本局玩家行为之前；
- 调试模式可显示真实计划，正常模式只显示玩家通过侦察获得的内容。

## 12. 数值与平衡框架

首轮数值不追求完整平衡，先满足以下可测关系：

- 中央高价值但更早接敌；侧翼高收益但情报成本更高；
- 同成本正面交战时，适配地形的战团应形成明显但可逆的优势；
- 火力群在有视野和掩护时强，在被突击单位接近后快速失去效率；
- 侦察带来的提前量足以改变部署决定，但侦察本身不能稳定占点；
- 首个预备队选择应在 30—60 秒内产生可观察后果；
- 改令和跨区支援存在真实时间成本，不能瞬间抹平先前决策。

关键试玩指标：

| 指标 | 目标问题 |
|---|---|
| 首次有效命令时间 | 玩家是否理解军团板和地图关系 |
| 每分钟改令次数 | Agent 是否需要过度纠正 |
| 卡牌与实体对应识别率 | 玩家是否明白一张卡展开成什么 |
| 情报查看到行动的延迟 | 报告是否可扫读、可用于决策 |
| 直接控制占比 | 粗细粒度是否都产生价值 |
| Agent 抢权事件 | 应为 0 |
| 不可解释失败比例 | 失败是否能追溯到可见原因 |
| 第二局意愿 | 不同编成和路线是否带来重玩价值 |

具体的盲测流程、战后提问、结构化观察员评估与单局判定见 [`PLAYTEST_PROTOCOL.md`](PLAYTEST_PROTOCOL.md)。人工答案与游戏自动记录分开保存，不进入权威模拟或敌方决策。

## 13. 美术与音频方向

### 13.1 视觉

- 战场保持克制、清晰、利于识别地形和射界；
- 卡牌视觉强调军用档案、编制和状态，不做高饱和收藏卡稀有度边框；
- 将领头像与部队徽记负责建立持续角色记忆；
- 实体数量应真实可见，但允许在远景使用编队轮廓和聚合标识；
- “可见、最后确认、推测”必须有稳定且可访问的视觉区分。

### 13.2 音频

- 命令回执区分将领性格和当前压力；
- 敌情、接敌、受阻、请求增援和总部受袭有不同警报层级；
- 远近战场声音帮助判断方向，但不泄露战争迷雾后的精确信息；
- 高频单位反馈聚合为部队级报告，避免百个实体同时播报。

## 14. 首个可玩切片范围

### 14.1 必须实现

- 《灰脊矿区》一张地图和八分钟胜负链；
- tick 0 战前军团编成：将领隶属、容量校验、战法、姿态及准确两张首发卡；
- 三名将领或等价指挥节点；
- 至少四张可部署/已部署部队卡，展开为不少于 40 个实体；
- 常驻军团卡牌板和地图联动；
- 将领卡拖向区域、姿态切换、部队卡直接路线/阵线、明确归还；
- 至少四张战法卡，可改变 Agent 行为；
- 补给周期、三个资源区、预备队投入和两项支援指令；
- 高/中/未知三类情报可信度与最后确认位置；
- 地形影响、四类核心战团、视野依赖和撤退；
- 数据锁定的敌方初始计划与反应规则；
- 战后损失回写到部队卡；
- 完整离线运行与确定性测试。

### 14.2 明确不做

- 随机抽牌、牌库构筑、卡包和稀有度系统；
- 单兵选择与逐单位微操；
- 完整基地建设、矿车采集和复杂生产科技树；
- 自然语言作为唯一输入；
- 在线多人、跨局大型战役、最终美术和商业化系统；
- 每个战场实体调用语言模型。

### 14.3 通过标准

陌生玩家完成一局后应能：

- 准确说明将领卡、部队卡和战法卡分别代表什么；
- 在 30 秒内通过拖动将领卡下达第一条有效命令；
- 根据一条带可信度的情报调整部署；
- 至少一次直接控制完整部队卡，并在完成后明确归还；
- 解释一个 Agent 为什么推进、停下、撤退或请求增援；
- 认识到敌方反应来自固定规则，而非系统临时读取选项作弊；
- 想尝试另一种编成、战法或主攻方向。

## 15. 主要风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 卡牌与战场脱节 | 玩家只看地图或只看卡面 | 卡牌、实体、路线、战损双向高亮并使用稳定 ID |
| Agent 需要频繁纠正 | 玩家退化为高负担微操 | 缩小意图语义，强化性格、姿态、战法和受阻反馈 |
| 细粒度仍过于复杂 | 百个实体造成操作过载 | 最低控制单位固定为部队卡，提供阵线工具而非个体框选 |
| 自动化削弱参与感 | 玩家只等结果 | 用资源投入、改令时机、战法配置和关键编队接管制造决策 |
| 固定敌人变得可背板 | 重玩性下降 | 多个开局前选定的计划模板、受控种子和公平反应表 |
| 百实体性能与拥堵 | 阵型破碎、寻路超预算 | 分层模拟、编队路径、局部槽位和规模压测，不让个体独立全局规划 |
| 长期成长滚雪球 | 老部队永远最优 | 荣誉与装备同时提高补充成本、形成专长与弱点 |
| 现有原型方向不同 | 基地 RTS 系统挤占新核心 | 复用权威模拟与 AI 边界，另建会战规则和卡牌领域层 |

## 16. 产品决策结论

本文确认 WARSEED 的“卡牌”采用以下定义：

1. 全部可见、持续存在，不随机抽取；
2. 将领卡代表指挥 Agent，部队卡代表真实编队；
3. 战法卡改变 Agent 的执行方式；
4. 荣誉与装备卡承载跨战斗成长与代价；
5. 地图上的约百个实体是这些卡牌的展开状态；
6. 玩家通过将领卡进行意图指挥，通过部队卡进行编队级直接操作；
7. 《灰脊矿区》的部署项属于总部预备编制，空中侦察与筑垒属于支援指令，均不构成随机战斗手牌。

这套定义同时保留了实时战场的不确定性、RTS 的空间与时间决策、Agent 指挥链的独特价值，以及卡牌在编成、成长和控制上的不可替代性。
