> 状态：执行基线

> 更新日期：2026-08-18
> 适用范围：《灰脊矿区》首切片完成后的完整 MVP 开发
> 历史说明：D-026 已取消本文中的真人证据硬门，D-027 已用 `GAMEPLAY_REWORK_ROADMAP.md` 取代后续领取顺序；本文件保留 P1-P6 实施记录。

## 1. 目标与完成定义

本计划把“增加内容”和“完善引导”落实为可验收的产品增量。最终目标不是简单增加卡牌数量，而是形成四场会战、持续军团成长、可回放教程和可重复自主试玩验证组成的完整 MVP。

整体完成必须同时满足：

- 四场会战均可从战前编成进入战斗、结算并回到下一场编成；
- 至少 5 名将领、12 张部队卡、12 张战法、6 项支援和 12 项荣誉/装备进入数据目录与合法性校验；
- 首局六步教程、上下文拒绝回执、战后解释和重开入口完整可用；
- 敌我继续使用同一命令、情报、寻路和战斗边界；每场敌方计划在读取玩家行动前锁定；
- 80 个常态实体与 120 个压力实体达到既定性能门；
- 自动回归、确定性矩阵、无干预模拟、自主行动脚本和真实键鼠完整试玩均通过；
- 至少一轮陌生玩家测试达到企划书的理解与操作门，问题已分级并回写。

## 2. 工作流与依赖

```text
企划条目 -> typed Resource / 场景数据 -> 权威模拟规则
        -> HUD 与教程反馈 -> 自动场景矩阵 -> 自主键鼠试玩
        -> 试玩记录与复盘 -> 平衡修订 -> 内容冻结
```

任何内容项都必须先定义玩家决策和验收证据，再进入实现。美术替换、数值扩张和关卡数量不能绕过命令边界、情报公平性或确定性要求。

### P5：会战 04《黑井反击》与成长扩充

状态：工程实现与自动化验收已完成（2026-08-18），陌生玩家理解度与平衡验收待执行。P5 是四关教学梯度的收束关，不再引入新的直接控制粒度；它把前三关已经学会的情报、路线、护送与增援判断放进同一场纵深反击，并首次要求玩家在“继续争胜”和“保存持续部队”之间做出可逆转战局但不可撤销部队投入的选择。

第四场已接入 `7168×4608` 地图、动态导航网格、五将领/十二部队卡/十二战法编成、六类支援、组织度、合法增援、整卡撤出、六项荣誉与六项装备、共享军团记录和专属六步教程。4×3 双跑确定性矩阵、smoke、Windows 导出、导出程序启动和 `1280×720` 真实键鼠全流程已经通过。人类试玩门仍不能由自动化替代。

#### P5.1 会战空间与胜负

- 地图尺寸为 `7168×4608`。敌方总部位于北部炼化厂，我方总部位于南部集结地；中轴不是单一路径，而是西部焦渣铁路、中央黑井设施、东部泵站高地和南部撤出走廊四个相互支援的战略区；
- 黑井设施提供较低补给但加快组织恢复，泵站高地改善火力视野，焦渣铁路适合装甲反击，撤出走廊不产资源且不参与常规占领；
- 摧毁敌方总部仍为胜利条件；我方总部被毁或时限耗尽为失败。主动撤出部队不会直接改变胜负，但会减少当前可用战力并保存该卡剩余实体；
- 敌方开局前在“中轴碾压”“铁路包抄”“泵站钳击”三套计划中锁定一套。反应只能读取敌方阵营知识、战略区状态和公开战损，不能读取玩家未提交的路线或撤出意图。

#### P5.2 组织度与有限撤出

- 每张已部署部队卡拥有 `0—100` 的权威组织度。实体承受伤害、成员失能和连续接敌会降低组织度；脱离接触后缓慢恢复，在黑井集结区或具备整编战法时恢复更快；
- `60—100` 为稳定、`30—59` 为受压、`1—29` 为动摇、`0` 为崩溃。组织度影响 Agent 的继续进攻、请求支援和撤离判断，不直接乘算武器伤害；
- 玩家把整张部队卡或其将领目标设为南部撤出走廊后，全部仍可行动成员进入撤出半径即将该卡标记为 `WITHDRAWN`。成员从战场移除但不计为战损，本局不能再次部署；
- 将领在组织度低于阈值、当前接触估计占优不足且后备部队不能使局部胜算转正时，可以提出撤出并执行退向走廊；玩家直接控制中的部队不会被自动撤出；
- 撤出、全灭、预备未投入和战场幸存必须在结算中区分，不能都折叠为“当前兵力”。

#### P5.3 内容补齐

- 新增两名将领：稳健的整编/防御将领“陆铮”和机会主义的机动/预备将领“顾寒星”，使全局可用将领达到 5 名；
- 新增四张部队卡：黑井警卫营、战场整补连、机动反击群、防空火力分队，使全局稳定部队卡达到 12 张；
- 新增六张战法：弹性防御、遭遇后脱离、战斗撤退、预备队投入、相互支援、集结整编，使全局战法达到 12 张。每张战法至少改变任务半径、激活时机、支援阈值、撤离阈值或组织恢复中的一项，并同时带来暴露、速度、战力投入或时间代价；
- 新增火力覆盖、快速机动和前线后勤三类支援，与现有空中侦察、紧急筑垒和战场补员共同构成 6 类支援；
- 荣誉/装备改为数据驱动池，共 6 项荣誉和 6 项装备。每张部队卡最多挂一项荣誉和一项装备，选择后必须显示收益、代价、费用和改装日，不能只提供单一固定按钮。

#### P5.4 共享成长与迁移

- 四场会战读取同一份持续军团记录，按稳定卡牌 ID 合并本场出现的卡；切换会战不再创建互不相干的战损副本；
- 旧的单会战记录在首次加载时按卡牌 ID 迁移，冲突时保留更低现员、更高累计战损和已有成长，不静默回满；
- 结算保存现员、累计战损、组织度、撤出状态、荣誉、装备、补充点、功勋和战役日。下一场应用记录时，只修改内容包中真实存在的同 ID 卡牌；
- “完全重开”先归档共享记录，再清空军团成长、教程本局进度和本场结果；教程启用偏好保持独立。

#### P5.5 专属教程与验证矩阵

专属六步教程依次验证：识别组织度、给两名将领不同目标、观察一次合法增援、将整卡送入撤出走廊、在结算中选择成长、返回作战区确认同卡状态。教程只消费已接受命令、阵营可见快照与结算记录，不强制玩家牺牲指定部队，也不读取敌方隐藏强度。

4×3 决策矩阵至少覆盖：无干预、集中反击、保存残部、贪占资源四种策略与三套敌方计划，并双跑确定。另设失败路径验证全部主力撤出后仍会因时限失败、隐藏敌人不会触发增援判断、已撤出卡不能再次部署、组织恢复不会越界。真实键鼠自测必须完成战前五将领编成、双轴命令、至少一次整卡撤出、结算成长选择、返回作战区和第二场读取。

退出条件：第四场可从作战区完整进入并返回；共享战损、组织和成长会改变下一场同 ID 卡牌；至少三种成长选择在 UI 和模拟中呈现不同收益与代价；全灭、撤出、胜利、失败、迁移和完全重开均有自动化；统一发布门、Windows 导出和完整键鼠自主试玩通过。

### P6：完整 MVP 收敛

P6 不再增加第五张地图或新的直接控制粒度。它只收敛四关已有系统、降低新手误操作、建立完整发布证据。

#### P6.1 四关教程进度与重播

交付：教程存档从全局开关迁移为逐会战的“未开始、进行中、已完成、已跳过”；作战区显示所选会战状态并提供从头重播；战前开关只影响当前会战；旧存档保守迁移，黑井成长连续性字段保留。

证据：单元测试覆盖 v1 迁移、逐关隔离、完成、跳过和重播；真实鼠标点击覆盖作战区重播、进入战前界面及 `1280×720`、`640×800` 布局。

失败路径：重播不得清空战损、组织、补充点、功勋、荣誉、装备或战役次数；一关跳过不得关闭其他三关。

退出条件：四关状态可独立保存和重置，重播后从该关第一步开始，军团记录逐字节保持不变。

#### P6.2 上下文回执与操作指引收敛

状态：已完成（2026-08-18）。28 个结构化拒绝原因全部映射到双语合法下一步；11 种目标模式在添加航路点、提交失败或选择变化后仍持续显示当前控制方式。真实《断桥回声》流程已通过鼠标提交不可达路线、保持规划模式、读取原因/建议/控制键并按 `C` 取消，截图确认指引位于地图外且无重叠。

交付：把路线取消、不可达、补给不足、控制权冲突、无合法目标和增援条件整合到同一回执层；只在相应输入模式中显示当前有效按键；战前和战中字段提供短提示，不新增遮挡地图的模态说明。

证据：每类拒绝原因有命令级测试和至少一次真实输入命中；中英文即时切换后按键与原因同步刷新。

失败路径：拒绝命令不能推进教程、改变资源或留下半完成输入模式；Esc 与路线取消键职责不得冲突。

退出条件：测试清单中的操作均可在游戏内找到入口、取消方法和失败原因，无需外部说明文档。

#### P6.3 四关串联自主试玩

状态：已完成（2026-08-18）。新增真实鼠标/键盘四关串联脚本，并在两个全新隔离会话中完整通过。两轮均记录四套锁定敌方计划、四次结算、`battle_count=4`、共享卡牌继承、`rescue_citation` 成长和累计 13 点补员；十二卡结算列表通过稳定卡牌 ID 与滚动到行后的真实点击验证。固定的直取总部诊断输入四关均失败，因此该证据只关闭流程、失败恢复与持续性风险，不关闭平衡和陌生玩家理解度风险。

交付：新增从作战区依次进入四场会战、结算、成长、返回并读取共享卡牌的自动流程；记录每关敌方计划、输入序列、结果、战损、成长和持续时间。

证据：隔离用户目录下的四关串联至少完整运行两次；固定输入和种子得到一致权威结果，允许渲染帧耗时不同。

失败路径：中途失败、主动返回、全灭、撤出和重启后均能回到合法入口，不产生无法恢复的空军团。

退出条件：一份新档可不借助调试写入完成四场入口到结算的往返，并在第四场看到第一场同 ID 卡牌的继承状态。

## 4. 教程实现规格

教程状态机只消费三类事实：已接受玩家命令的结构化描述、阵营可见 `WorldSnapshot`、战役结算信号。它不读取隐藏真值，也不直接修改模拟。

教程步骤支持以下状态：`LOCKED`、`ACTIVE`、`SATISFIED`、`SKIPPED`、`COMPLETE`。已满足事实按步骤 ID 保存于本局内存，允许玩家乱序操作；界面只显示当前最早未满足步骤。教程偏好独立于部队战损存档，清空战役不应造成无法重新进入教程。

界面约束：

- 桌面布局放在左侧栏，窄屏放在地图下方的既有操作区；
- 不使用居中模态框，不拦截地图鼠标，不自动暂停；
- 标题、当前步骤、完成条件和跳过按钮在 232 像素宽度内无水平溢出；
- 当前目标关联的卡牌或按钮可使用颜色/边框提示，但不强制焦点跳转；
- 所有快捷键只在相关输入模式中显示，以当前键位映射为准。

## 6. 自主试玩验证

验证分为四层，不能用低层测试替代高层体验证据：

| 层级 | 方法 | 证明内容 |
|---|---|---|
| L1 | 纯模拟与单元测试 | 命令、状态机、战斗、经济、持久化和确定性 |
| L2 | headless 场景矩阵 | 多策略、多个敌方计划、无干预战斗和胜负可达性 |
| L3 | UI 自动操作 | 真实场景节点、鼠标命中、键盘取消、教程推进、分辨率适配 |
| L4 | 完整键鼠自主试玩 | 从编成、首局教程、会战到结算和第二局的实际可用性 |

每个会战至少保留：推荐方案、保守方案、情报优先方案、资源贪婪方案、无干预方案和故意失败方案。自主试玩报告必须记录版本、分辨率、输入序列、敌方计划 ID、结果、持续时间、步骤完成、拒绝命令、战损和截图；失败应回到具体规则或界面，而不是只写“手感不好”。
