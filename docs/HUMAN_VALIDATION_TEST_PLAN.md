# WARSEED 可选真人研究测试方案

> 版本：1.0
> 建立日期：2026-08-21
> 当前状态：`OPTIONAL_NOT_RUN`，不属于工程、阶段或发布门禁
> 工程基线：R1 类型化目标与结果系统，`SIMULATED` 完整门已通过
> 关联协议：[`PLAYTEST_PROTOCOL.md`](PLAYTEST_PROTOCOL.md)、[`P6_7_PLAYTEST_COHORT_PLAN.md`](P6_7_PLAYTEST_COHORT_PLAN.md)

## 1. 目的与结论边界

本方案保留可用于产品研究的真人用例，但自 D-026 起不再是工程实现、阶段出口、发布候选或后续开发的必需条件。AI 自主试玩、规则代理、headless 测试、五档分辨率矩阵和开发者自测只能记为 `SIMULATED`；本文件中的用例只有由符合前置条件的真人执行，并保留规定证据后，才能记为 `HUMAN/PASS`。未执行时保持 `OPTIONAL_NOT_RUN`，不得阻塞工作项。

真人不必与开发机处于同一地点。以下三种方式均有效：

1. **本机坐席**：参与者在开发机或独立测试机操作，观察员现场记录；
2. **远程观察**：参与者通过屏幕共享操作其本机游戏，观察员只观看和提问；
3. **分发试玩包**：向参与者发送冻结的 Windows ZIP，参与者本地运行，结束后回传匿名日志、评估表和必要截图/录屏。

远程桌面由观察员代替玩家点击不算真人操作证据。网络串流造成的输入延迟、画面压缩或断线必须记录，不能归因于游戏。

## 3. 角色与证据

| 角色 | 职责 | 禁止事项 |
|---|---|---|
| 参与者 | 独立操作、用自己的语言解释、决定是否继续 | 看源码、企划、标准答案或他人场次 |
| 观察员 | 计时、记录行为、战后提问、标记环境问题 | 提示路线、按钮、目标答案或替玩家操作 |
| 构建管理员 | 冻结包、校验哈希、分配匿名 ID | 在 cohort 中途替换文件 |
| 评审者 | 审核证据完整性、分级缺陷、给出放行建议 | 把缺失证据记为通过 |

每场至少保留：

- 原始 `latest_<scenario>.json` 或归档记录；
- 独立 `*_assessment.json`；
- 匿名参与者 ID、观察员 ID、构建哈希、会战 ID、开始时间和局号；
- 实际分辨率、指针设备、界面语言、是否远程；
- 关键问题的玩家原话或明确行为证据；
- P0/P1 问题的截图或录屏时间码；
- 任何观察员提示的时间和内容。

证据状态只允许：`NOT_RUN`、`PASS`、`FAIL`、`INCOMPLETE`、`INVALID`、`RETEST_REQUIRED`。缺少玩家原话、原始日志或构建身份时使用 `INCOMPLETE`，不能使用 `PASS`。

## 4. 执行批次

### 4.1 最小工程人工检查

用途：每次候选构建先由 1 名未参与该功能实现的测试者执行，发现明显阻塞。该批次不能替代陌生玩家 cohort。

- 1 人；
- 执行 `HV-BUILD-001`、`HV-R1-001` 至 `HV-R1-006`、`HV-UI-001`；
- 发现 P0/P1 时停止分发并修复；
- 通过后才进入 4.2。

### 4.2 陌生玩家正式 cohort

沿用 P6.7 预注册覆盖：9 名独立陌生玩家、24 个最低场次，灰脊 9 份，其余三关各 5 份，3 人完成四关连续流程。至少 3 人使用 1280x720 或更小显示区域，至少 2 人使用触控板，至少 4 人使用鼠标，至少 7 人使用中文界面。

每名参与者执行其分配会战中的 `HV-P67-001` 至 `HV-P67-008`；后三关追加 `HV-R1-001`，完整串联玩家追加 `HV-E2E-001`。

### 4.3 专项机制批次

护送胜利和有序撤离目前是工程测试资源，不是四关正式玩家入口。执行 `HV-R1-004` 与 `HV-R1-005` 前，必须由后续候选版提供可从 QA 菜单进入的冻结场景；测试者不能通过编辑器、脚本或控制台触发结局。

## 5. 测试用例

### HV-BUILD-001 候选包完整性与首次启动

- **优先级**：P0
- **前置条件**：冻结 ZIP、SHA-256 与 manifest 已发布；测试机未安装源码工程。
- **步骤**：校验 ZIP 哈希；完整解压；从包内启动；创建全新匿名会话；进入作战区并开始灰脊。
- **期望结果**：哈希一致；EXE 与 PCK 同目录；无需 Godot 编辑器；没有安全错误、缺文件、黑屏或读取其他玩家存档；日志记录正确构建与匿名 ID。
- **证据格式**：构建校验文本、启动截图、原始会话目录清单、测试机 Windows 版本。

### HV-P67-001 首次接触与首条有效命令

- **优先级**：P0
- **前置条件**：从未看过 WARSEED 操作资料的参与者；灰脊新会话；观察员不提示。
- **步骤**：参与者自行完成战前编成并开始会战；从进入战场开始计时；记录首条有效将领或部队卡命令。
- **期望结果**：能完成编成并进入会战；30 秒内出现有效命令；拒绝命令有可理解原因；无入口不可见或无法继续。
- **证据格式**：原始日志中的编成耗时、首命令时间、接受/拒绝 reason；观察员时间码与简短记录。

### HV-P67-002 部队卡与地图实体对应

- **优先级**：P1
- **前置条件**：完成至少一次选择、部署或接管。
- **步骤**：战后询问“一张部队卡和地图上的单位是什么关系？”；要求参与者在界面中指出一张卡及其对应实体。
- **期望结果**：参与者理解一张卡代表完整真实编队，不是单一车辆、抽取手牌或纯数值加成。
- **证据格式**：玩家原话；指出卡牌与实体的截图或录屏时间码；`card_entity_recognition` 结论。

### HV-P67-003 将领 Agent 行为解释

- **优先级**：P1
- **前置条件**：至少一名将领执行过移动、接敌、等待、撤退或支援任务。
- **步骤**：让参与者选择一次将领行为并解释原因；允许其查看游戏内理由、风险和退出条件。
- **期望结果**：解释与可见目标、姿态、战法、情报或退出条件一致；不要求猜测隐藏敌情。
- **证据格式**：玩家原话、所指将领/行为、对应 UI 截图、`commander_behavior_explanation`。

### HV-P67-004 敌方反应与公平情报理解

- **优先级**：P1
- **前置条件**：本局出现至少一次结构化敌方反应。
- **步骤**：战后让参与者解释该反应为何发生；追问其是否认为敌方读取了玩家未暴露的信息。
- **期望结果**：参与者能把反应关联到预先锁定计划或已暴露行动；没有明确的“读心作弊”体验证据。
- **证据格式**：反应 ID/时间、玩家原话、观察员结论、必要时录屏片段。

### HV-P67-005 情报到决策闭环

- **优先级**：P1
- **前置条件**：出现带可信度的新情报。
- **步骤**：不提醒参与者；观察其是否在情报后改变部署、目标、支援或直接控制；战后询问该情报是否影响决定。
- **期望结果**：至少一次有效玩家行动可追溯到新情报；参与者能说明情报的不确定性或时效。
- **证据格式**：情报与后续命令时间戳、玩家原话、`intel_followed_by_player_action`。

### HV-P67-006 整卡接管与归还

- **优先级**：P0
- **前置条件**：至少一张已部署部队卡。
- **步骤**：参与者自行找到整卡接管；下达路线/阵线命令；明确归还将领；观察 Agent 是否抢权或单位是否瞬移。
- **期望结果**：整卡所有成员同时进入玩家控制；玩家命令生效；归还经过合法归队过程；Agent 不覆盖直接控制命令。
- **证据格式**：takeover/return 日志、命令结果、录屏时间码、冲突 reason。

### HV-P67-007 不依赖单体诊断模式

- **优先级**：P1
- **前置条件**：完整一场灰脊。
- **步骤**：观察参与者是否寻找逐单位微操；不介绍 `F3`；若其自行发现则记录原因和后续行为。
- **期望结果**：参与者可只用将领与整卡控制完成结算；单体诊断不是核心流程的必要条件。
- **证据格式**：诊断模式启用次数、玩家原话、观察员记录。

### HV-P67-008 重玩意愿与替代方案

- **优先级**：P2
- **前置条件**：完成胜利或失败结算。
- **步骤**：询问是否愿意换编成、战法、路线或主攻方向再打一局，以及想改变什么。
- **期望结果**：至少能提出一种与首局不同且受规则支持的方案；正式 cohort 至少 6/9 人明确愿意重玩。
- **证据格式**：玩家原话、方案分类、`second_battle_intent`。

### HV-R1-001 目标 UI 可见性与理解

- **优先级**：P0
- **前置条件**：四关任一正式会战；中文和英文各至少一轮；隐藏调试层。
- **步骤**：进入会战后让参与者指出当前主要胜利、失败和剩余时间条件；目标状态变化后再次询问；观察窄屏是否需要异常滚动或遮挡战场。
- **期望结果**：目标名称与状态在 HUD 中可见；参与者能区分完成、进行中与失败；不会把资源区状态误认为唯一胜利条件；文本不截断关键含义。
- **证据格式**：分辨率、语言、目标 HUD 截图、玩家复述、遮挡/截断记录。

### HV-R1-002 总部胜负等价迁移

- **优先级**：P0
- **前置条件**：冻结正式会战；分别准备可摧毁敌方总部与可让己方总部失守的场次。
- **步骤**：完成敌总部摧毁；另局完成玩家总部失守；记录触发到结算的时间与结算次数。
- **期望结果**：敌总部摧毁只结算一次胜利；玩家总部失守只结算一次失败；结束后战场不再推进，新命令被明确拒绝；战损只写入一次。
- **证据格式**：两局原始日志、结算截图、军团记录前后 diff、命令拒绝 reason。

### HV-R1-003 超时失败与结算原因

- **优先级**：P1
- **前置条件**：正式会战；允许自然等待到时间结束，不使用脚本改 tick。
- **步骤**：未摧毁双方总部时等待计时归零；查看 HUD 与战后结算；点击再次作战。
- **期望结果**：只结算一次失败；界面说明失败来自时间条件而非总部被毁；再次作战回到 tick 0，计时和目标状态重置。
- **证据格式**：归零前后录屏、结算原因文本、重开截图、日志 outcome reason。

### HV-R1-004 护送成功的非总部胜利

- **优先级**：P0
- **前置条件**：候选版提供玩家可进入的冻结护送 QA 场景；目标 HUD 已接入；参与者不知道通过答案。
- **步骤**：先让参与者解释护送对象和目的地；不摧毁敌总部，把目标编队完整护送到目标区；另局让护送对象失效。
- **期望结果**：抵达后权威胜利且敌总部仍存活；失败局不会错误胜利；HUD、结算和日志引用同一目标 ID 与原因；参与者能在行动前理解规则。
- **证据格式**：两局原始日志、敌总部存活证据、目标/结算截图、玩家复述。

### HV-R1-005 有序撤离与普通失败区分

- **优先级**：P0
- **前置条件**：候选版提供玩家可进入的冻结撤离 QA 场景；军团记录使用隔离会话。
- **步骤**：按目标撤出规定部队并保留总部条件；另局让总部先失守；比较战后结果、奖励、战损和持久化记录。
- **期望结果**：第一局显示“有序撤离”而非胜利/普通失败，并使用独立奖励档位；第二局为失败；两者 reason、grade 和军团记录可区分且只写入一次。
- **证据格式**：两局结算截图、`last_result/grade/reason`、奖励与卡牌战损 diff、玩家对差异的复述。

### HV-R1-006 结算文本、声音与多语言一致性

- **优先级**：P1
- **前置条件**：至少覆盖胜利、失败、有序撤离各一局；中文与英文界面。
- **步骤**：观察结算前反馈、结果标题、原因文本和按钮；切换语言后复查；关闭音频后重复关键结算。
- **期望结果**：结果、原因和颜色/声音不互相矛盾；静音时文本与视觉仍完整；切换语言不改变 outcome；按钮可见且可操作。
- **证据格式**：中英文截图、音频开关状态、玩家复述、任何文本截断记录。

### HV-UI-001 五档分辨率与真实指针操作

- **优先级**：P1
- **前置条件**：1280x720、1920x1080、2560x1600、640x800、480x800；至少一次鼠标和一次触控板。
- **步骤**：在每档检查作战区、战前编成、暂停菜单、战后结算和反馈问卷；完成滚轮地图缩放、面板滚动、拖拽将领、整卡接管、开始/返回/反馈按钮操作。
- **期望结果**：关键文本和命令不重叠；地图区域可操作；面板滚轮不缩放地图；所有关键按钮可达；触控板不会造成不可恢复的拖拽或缩放状态。
- **证据格式**：每档五个界面截图、设备类型、失败操作时间码、完成清单。

### HV-A11Y-001 可辨识性、焦点与非颜色提示

- **优先级**：P1
- **前置条件**：至少一名自报存在色觉、低视力、精细操作或阅读困难的参与者，或由无障碍测试人员执行。
- **步骤**：仅凭文字/形状识别友敌、目标状态和结果；使用键盘导航暂停/结算界面；检查长时间阅读、字号和闪光反馈。
- **期望结果**：关键状态不只依赖颜色或声音；焦点可见且顺序合理；没有必须精确点按的隐藏入口；参与者能说明造成困难的具体元素。
- **证据格式**：匿名需求类别、任务完成结果、玩家原话、截图/录屏、建议严重级。

### HV-E2E-001 四关连续军团流程

- **优先级**：P0
- **前置条件**：同一匿名 ID、同一冻结构建；按灰脊、断桥、雾林、黑井顺序；不可重置失败或战损。
- **步骤**：连续完成四关结算；每关进行至少一次编成或成长选择；黑井检查继承的战损、组织与成长；退出后使用 `-Resume` 复查。
- **期望结果**：四关各生成独立记录；共享 roster `battle_count` 为 4；黑井读取此前状态；失败、重开、暂停和恢复不会污染其他参与者或重复奖励。
- **证据格式**：四关日志、军团记录版本和 diff、最终结算截图、恢复启动记录、玩家对跨关后果的解释。

### HV-E2E-002 单场完整节奏与疲劳

- **优先级**：P2
- **前置条件**：未参与实现的玩家；一场完整会战，不加速时间。
- **步骤**：从战前编成玩到结算；观察无操作等待、高频改令、信息过载和视线切换；战后询问最无聊、最混乱和最想保留的时刻。
- **期望结果**：玩家能在不持续微操的情况下维持决策；没有持续两分钟以上且玩家不知道该做什么的无意空窗；疲劳问题可定位到具体界面或机制。
- **证据格式**：会战时长、改令/接管指标、关键时间码、三项玩家原话。

### HV-FB-001 战后反馈入口发现与完成

- **优先级**：P1
- **前置条件**：使用包含反馈功能的冻结构建；完成任一会战；观察员不提示入口位置。
- **步骤**：观察玩家能否在结算页找到“提供试玩反馈”；自行完成必填项、滚动到错误描述并提交；关闭后继续返回作战区。
- **期望结果**：入口可发现；玩家理解评分对象与匿名说明；必填错误可恢复；提交/关闭不影响结算、成长或返回流程。
- **证据格式**：构建哈希、语言、分辨率、发现耗时、完成耗时、玩家对隐私说明的复述、失败操作时间码。

### HV-FB-002 离线保存与恢复发送

- **优先级**：P0
- **前置条件**：反馈服务器未启动；测试电脑可访问其 Godot 用户数据目录。
- **步骤**：提交一条带唯一复现短语的反馈；确认界面提示本地保存；退出并重新启动同一匿名会话；启动服务器后点击“重试待发送反馈”。

## 6. 缺陷分级与复测

| 等级 | 定义 | 处理 |
|---|---|---|
| P0 | 崩溃、存档破坏、无法完成流程、错误结算或重复奖励 | 立即停止该构建全部真人测试；修复后完整重跑相关 P0 与 E2E |
| P1 | 关键入口不可发现、目标误解、控制权冲突、严重遮挡或三人重复理解失败 | 建立独立工作项；修复后用未见过修复的新玩家复测 |
| P2 | 不阻塞但持续降低理解、节奏、反馈或可访问性 | 修复或由产品负责人书面接受具体风险 |
| P3 | 外观、措辞或低频便利性问题 | 进入普通 backlog，不阻止工程阶段 |

修复不得通过修改原始证据、降低预注册阈值或删除失败场次获得通过。每次复测必须记录新构建哈希和与原问题的关联 ID。

## 8. 回传给 AI 的最小材料

把证据放入仓库可读目录，例如 `artifacts/playtests/<candidate-id>/`，然后发送：

```text
/goal review human-validation
starting_evidence:
  - artifacts/playtests/<candidate-id>/
focus:
  - 构建哈希与匿名会话是否一致
  - 原始日志与 assessment 是否逐项对应
  - P6.7 样本和环境覆盖
  - HV-R1、HV-UI、HV-A11Y、HV-E2E、HV-FB 的 PASS/FAIL/INCOMPLETE
  - P0/P1/P2 缺陷与复测需求
write_changes: false
stop_when:
  - 原始证据缺失、构建混用或需要观察员补充玩家原话
```

AI 可以校验、汇总和生成候选缺陷清单，但不能补写玩家回答、替观察员判定未观察项目，或把 `SIMULATED` 结果升级为 `HUMAN`。是否把研究发现转为正式工作项由产品负责人决定。
