# 系统设计

## 设计目标

系统要保证高层目标能够稳定转化为地图行动，同时让玩家随时拥有最终控制权。MVP 优先采用可测试的任务模板、规则调度和状态机；语言模型未来可以把自然语言转换成结构化命令，但不直接控制单位或计算战斗结果。

## 分层架构

```text
玩家输入层
├─ 直接单位命令
└─ 结构化高层命令
        ↓
目标与任务层
├─ 战略目标
├─ Agent 任务
└─ 单位动作
        ↓
控制权仲裁层
├─ 单位归属
├─ 玩家临时接管
├─ 命令优先级
└─ 暂停、取消与恢复
        ↓
Agent 决策层
├─ 主 AI／参谋长
├─ 工业主管
└─ 战场将领
        ↓
游戏模拟层
├─ 移动与寻路
├─ 战斗
├─ 采矿
├─ 建造与维修
└─ 生产
        ↓
反馈层
├─ 目标、路线与编队标记
├─ 任务状态与受阻原因
├─ 敌情与事件记录
└─ 警报和摘要
```

## Godot 实现映射

详细实现基线见 [Godot 技术方案](TECHNICAL_PLAN.md)。抽象分层在 Godot 中映射为：

```text
InputController / HUD / Agent
        ↓
GameCommand → CommandValidator → CommandQueue
        ↓
SimulationHost → SimulationWorld
        ↓
SimulationEvent / WorldSnapshot
        ↓
WorldPresentation / HUD / DebugLayer
```

`SimulationWorld` 保存唯一权威状态，`SimulationHost` 只负责固定 tick 适配和事件发布。显示节点通过稳定 `EntityId` 绑定模拟实体；Godot `Node`、动画、场景树和 HUD 不得成为第二份战局真相。`simulation` 模块不能依赖具体场景、输入、UI 或音频。

## 权威边界

Agent 与玩家界面都必须实例化同一类 `GameCommand`，并通过同一个 `CommandValidator` 影响模拟，例如移动、攻击、采集、排队生产和开始施工。验证通过的命令进入 `CommandQueue`，只在权威模拟 tick 边界应用；表现节点不能绕过该路径。

Agent 不得：

- 直接改变单位位置、生命值或资源；
- 跳过建造和生产时间；
- 读取玩家尚未获得的精确敌军信息；
- 在单位被玩家接管后继续发送覆盖命令；
- 用自由文本直接驱动未经验证的底层动作。

这条边界使行为可回放、可调试、可取消，也便于未来进行同步和自动测试。

## 模拟步进与处理顺序

- `SimulationWorld` 初始以 10 Hz 固定 `SimulationTick` 推进，渲染目标为 60 FPS并在快照之间插值；
- 输入逐帧采集，但只转换为命令，不能直接修改模拟；
- 模拟使用项目封装的固定种子随机源，表现随机与模拟随机分离；
- 同一 tick 集中按“命令与控制权 → 任务/意图 → 移动 → 经济/生产 → 战斗/死亡 → 胜负 → 事件/快照”处理；
- 结算不得依赖 SceneTree 遍历顺序；
- 10 Hz 是初始可测量基线，若手感或精度不足，应统一调整并更新决策记录。

## 导航与编队边界

首个切片使用 `TileMapLayer` 生成独立逻辑格，以 `AStarGrid2D` 处理静态全局路径。编队由项目自定义 formation slots、简单 separation、卡住检测和狭窄通道纵队降级完成。动态单位不逐个永久写入全局阻挡格，也不逐帧重算路径。

玩家接管成员时，该成员的 slot 释放或标为空；归队时选择安全 rejoin point 并重新分配，禁止瞬移。只有在 10—15 个单位规模下仍长期拥堵或导航预算超限时，才升级到 `NavigationServer2D`、流场或复杂局部避障。

## 命令优先级

优先级从高到低：

1. 玩家直接单位命令；
2. 玩家结构化高层命令；
3. Agent 当前任务；
4. 单位默认安全行为。

高优先级命令发生时，低优先级任务必须暂停或重新规划，不能在下一帧抢回控制权。

## 单位控制状态

每个可控单位至少具有以下状态：

- `PlayerControlled`：由玩家持续管理；
- `AgentAssigned`：归指定 Agent 和任务管理；
- `TemporarilyOverridden`：原属 Agent，但已被玩家临时接管；
- `Unassigned`：可用但尚无任务；
- `Disabled`：死亡、失能或处于不可接受命令的状态。

单位还要记录：当前控制者、原编队、当前任务、最后合法命令、接管原因和可归还目标。

### 接管流程

1. 玩家向 Agent 管理的单位发出直接命令；
2. 单位立即进入 `TemporarilyOverridden`；
3. 原 Agent 从可调度成员中排除该单位，并更新任务容量；
4. 玩家继续操作，Agent 不覆盖命令；
5. 玩家选择返回原编队、留在当前位置、加入另一编队或继续手动；
6. 归队时由编队选择安全集结点，恢复任务而非瞬移。

不得使用几秒无操作后自动抢回的隐式机制。

## 三层任务模型

### 战略目标

由玩家决定“要什么”，例如优先发展经济、控制中央矿区、保证基地安全、从西侧进攻。

### Agent 任务

由参谋长按已定义的任务模板拆解，例如侦察中央矿、增加矿车、建立守备队、修建兵工厂、集结进攻部队。

### 单位动作

由基础单位执行移动到坐标、采集矿石、施工、攻击指定目标、保持距离或进入维修范围。

参谋长不越过中间层逐帧操作单位；基础单位不自行改变战略目标。

## 任务生命周期

每项高层目标和 Agent 任务使用统一状态：

- `Waiting`：等待资源、单位或前置任务；
- `Preparing`：预留资源、选址、分配单位或集结；
- `Executing`：正在执行；
- `Paused`：被玩家或高优先级任务暂停；
- `Blocked`：当前无法推进；
- `Completed`：满足验收条件；
- `Failed`：已无法完成且没有安全恢复方案；
- `Cancelled`：被玩家或上层任务取消。

`Blocked` 必须给出机器可读原因和用户可读说明，例如资源不足、没有可用工程车、路径不可达、编队人数不足、目标威胁过高或关键单位被玩家接管。

任务支持暂停、取消、修改目标、调整参与单位、调整优先级和修改撤退条件。

## 资源与目标冲突

### 全局优先级

玩家可选择：经济优先、军事优先、防守优先或均衡。该设置用于解决日常资源冲突，不应频繁弹窗。

### 资源预留

任务记录总成本、已预留资源、当前缺口和开始条件。紧急守军可以依据防守优先级抢占普通生产预算；玩家直接生产命令优先于 Agent 计划。

只有两个明确的高层目标无法同时满足、且既定优先级不能解决时，参谋长才请求玩家选择。

## 主 AI／参谋长

职责：

- 校验玩家高层命令；
- 选择预定义任务模板并分派给对应 Agent；
- 汇总资源、生产、敌情、编队和受阻状态；
- 检测跨 Agent 冲突；
- 向玩家报告需要决策的异常。

MVP 不实现任意自由规划器。“占领矿区”等目标使用可检查的任务图：侦察、评估威胁、集结护卫、派出采集/施工单位、建立防守、开始采集、持续监控。

## 工业主管

维护矿区、矿车、工程车、建筑、损伤、生产队列和资源预算。

第一版能力：

- 将矿车分配到指定矿区并循环采集；
- 遇敌时向已知安全点撤退；
- 管理指定生产计划；
- 在玩家指定区域内选择合法建筑位置；
- 显示蓝图后调度工程车施工；
- 报告资源、路径和单位受阻原因。

维修优先级和复杂经济优化在基础流程稳定后加入。

## 战场将领

维护被委托单位、编队、当前任务、最近接敌位置、敌军估算和损失。

第一版能力：

- 建立侦察组、守备队或单一突击队；
- 前往集结点；
- 防守指定区域且不追击超过半径；
- 沿玩家指定路线攻击目标；
- 让突击车保持前排、导弹车保持后排；
- 达到损失阈值时撤退并报告；
- 在关键单位被接管后继续管理剩余成员。

进攻、防守和撤退条件必须数据化，避免不可解释的随机切换。

## 基础单位行为

单位使用简单状态机完成单一职责：

- 矿车：前往矿点、采集、返仓、卸载、循环、遇敌逃生；
- 工程车：前往工地、施工、维修、撤离；
- 侦察车：移动、观察、避战、报告；
- 战斗车：寻路、保持阵位、索敌、攻击、停止和撤退。

默认安全行为只处理迫在眉睫的局部危险，不能自行改变上层目标。

## 敌情与战争迷雾

玩家方 Agent 只能使用：

- 当前视野中的敌人；
- 已探索地形；
- 敌人最后已知位置、时间和当时兵力；
- 由侦察任务产生的报告。

报告要表达不确定性，例如“西侧路线 45 秒未侦察”，而不是把未知信息伪装成事实。

## 可解释反馈

每项活动中的任务至少显示：

- 发起者与负责 Agent；
- 战略目标和当前阶段；
- 参与单位与缺员情况；
- 地图目标、集结点和计划路线；
- 资源预算与预计开始条件；
- 撤退或完成条件；
- 最近重要事件；
- 暂停、受阻或失败原因；
- 可用的暂停、取消、修改和接管操作。

普通状态变化进入事件记录；只有基地受袭、关键任务失败、严重目标冲突等事件使用强警报。

## 可测试性要求

- 纯 `SimulationWorld` 测试无需加载主游戏场景；
- 任务模板、阈值与单位属性使用 typed custom `Resource` 和文本 `.tres`；
- 固定随机种子、初态和命令序列应产生相同关键状态/事件摘要；
- 命令、控制权转换和任务状态变化写入结构化事件日志；
- 支持 Godot headless 加速运行经济、战斗和敌方阶段流程，并返回可靠退出码；
- 对 UI 和 Agent 参数化测试，证明二者经过相同 `CommandValidator`；
- 自动测试覆盖命令优先级、资源预留、接管归队、任务取消、不可达路径与 Agent 不作弊；
- GUT 仅是待技术 spike 的候选，兼容性验证前不作为已采用依赖。

## 仍待验证的问题

- Windows 最低硬件和正式性能预算；
- 10 Hz 是否满足最终移动与战斗手感；
- GUT 是否正式采用及固定版本；
- 局部避障是否达到升级触发条件；
- 完整回放格式与未来多人同步边界；
- 美术资产来源、许可和 Git LFS 启用阈值；
- 自然语言功能进入 post-MVP 的条件。
