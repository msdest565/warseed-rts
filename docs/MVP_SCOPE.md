# WARSEED MVP 范围

> 产品方向以 [整合版游戏企划书](GAME_DESIGN_DOCUMENT.md) 和 D-017 为准。现有基地 RTS 技术切片是迁移基础，不是本文件定义的新 MVP。D-026 已取消本文中的真人证据硬门，D-027 后实施顺序以 `GAMEPLAY_REWORK_ROADMAP.md` 为准。

## 1. 验证目标

MVP 要回答五个问题：

1. 常驻卡牌能否自然表达军队编成、战场实体和持续损失；
2. 玩家能否理解并信任具名将领 Agent 的行动；
3. 将领级意图与部队卡级直接操作是否都具有不可替代的价值；
4. 不完整情报和固定敌方计划能否形成公平、可复盘的决策；
5. 约百实体的战场能否通过少量卡牌保持清晰、稳定和可操作。

## 2. 首个垂直切片：《灰脊矿区》

### 2.1 对局边界

| 项目 | 规格 |
|---|---|
| 模式 | 单人 1v1 规则 AI |
| 地图 | 灰脊矿区，南北总部与三个横向资源区 |
| 时长 | 5—8 分钟，八分钟时限 |
| 胜利 | 时限内摧毁敌方总部 |
| 失败 | 己方总部被摧毁；同 tick 双方总部被摧毁也算失败 |
| 运行 | Windows first、离线、无 LLM 依赖 |
| 权威模拟 | 固定 10 Hz，玩家与 Agent 共享命令边界 |

### 2.2 地图

```text
                       [敌方总部]
                           |
       西部矿场 ------ 中央中继站 ------ 东部补给站
       开阔地             城镇废墟          林地
       +2 补给            +1 补给           +2 补给
                         支援冷却加快
                           |
                       [我方总部]
```

- 每个资源区每 30 秒自动结算；
- 西部强调装甲展开，中央强调废墟近战，东部强调遮蔽与侦察；
- 未侦察区域没有可靠情报；
- 地图保存可见、最后确认和推测三类敌情状态。

### 2.3 资源与部署

- 开局补给 5/10；
- 基础收入每 20 秒 +1；
- 资源区按场景值周期产出；
- 补给用于投入总部预备编制和请求支援；
- 新部队部署需要 10 秒，不是瞬间出现；
- 人口限制当前战场实体总量；
- 不使用矿车、逐单位生产队列或基地科技树。

### 2.4 军团内容

切片至少包含：

- 2—3 名具名将领；
- 4 张以上部队卡；
- 4 张以上战法卡；
- 装甲、突击、火力、侦察四种核心战团；
- 不少于 40 个、目标 60—80 个真实战场实体；
- 两项总部预备编制：装甲矛头、雷鸣火力群；
- 两项支援指令：空中侦察、紧急筑垒。

会战开始前必须显示完整军团编成板：四张部队卡均可改挂合法将领，每名将领可选择战法与初始姿态，并准确选择两张首发卡。界面实时显示容量并阻止非法计划；提交前权威 tick 固定为 0，战场命令不得进入队列。

### 2.5 卡牌硬规则

- 所有卡牌始终可见，不抽取、不洗牌；
- 将领卡保存容量、性格、特长、战法槽和当前任务；
- 部队卡保存编制、现员、成员实体、位置、任务和战损；
- 战法卡装配到将领并改变其执行约束，不产生即时伤害；
- 战后损失至少回写到部队卡；
- 卡面现员必须由权威实体状态计算，不能由 UI 自行维护。

### 2.6 正式操作粒度

#### 将领级

- 拖动将领卡到地图区域；
- 把总部预备部队卡拖给其战前所属将领，正式投入增援；
- 设置谨慎、均衡、强攻、固守或脱离姿态；
- 修改目标、路线偏好和增援；
- 查看当前阶段、计划、风险和受阻原因。

#### 部队卡级

- 点击部队卡整队选择绑定实体；
- 绘制路线、阵线和朝向；
- 指定目标或防区；
- 完成关键操作后明确归还将领。

正式模式不允许选择单个成员。开发诊断模式可以保留个体选择，但测试成功路径不能依赖它。

会战内投入预备队不改变 `ArmyPlan` 的隶属关系。拖给其他将领必须以结构化原因拒绝；拖给所属将领时由系统选择总部附近、朝将领当前目标方向的合法展开点。点击预备卡后在地图精确选择展开点仍作为同一条权威部署命令的细粒度入口。

### 2.7 情报

每条报告至少包含：来源、时间、目标类别、估计数量、区域或位置、移动方向和可信度。空中侦察能覆盖两个相邻区域 20 秒。主 AI“枢机”负责合并报告和计算预计到达时间，但不推荐唯一最优答案。

### 2.8 敌方 AI

- 初始编成、计划模板、预备队、资源和反应表在开局锁定；
- 只能读取敌方阵营已获得的知识；
- 只通过合法 `GameCommand` 行动；
- 反应有数据化触发器、延迟、承诺时间和撤退阈值；
- 同一初态、种子和玩家命令序列产生一致关键结果；
- 调试层可显示计划与改令原因，正常 UI 不泄露隐藏信息。

## 3. P0 功能

- 将领、部队卡、战法与军团编制的 typed data/state/snapshot；
- 常驻军团卡牌板及卡牌与实体双向高亮；
- 部队卡整队选择和合法地图命令；
- 多将领、多部队卡独立任务与控制权仲裁；
- 将领目标、姿态、战法行为约束与明确归还；
- 三个资源区、补给、人口、预备部署和支援指令；
- 四类战团与开阔地/废墟/林地的最小战术规则；
- 情报来源、可信度、最后确认位置和区域报告；
- 锁定计划的公平敌方 AI；
- 总部胜负、八分钟时限、战损回写；
- 40/80/120 实体性能基线与自动回归。

## 4. P1 功能

- 路线和阵线绘制的完整交互与预览；
- 将领性格差异的实时行为反馈：权威状态与快照已提供“当前行动 + 结构化原因 + 变更 tick + ETA 区间 + 风险/依据 + 退出条件”，军团板已覆盖姿态、战法等待、接敌/规避、受阻、接管和归队；风险只使用合法阵营接触与结构化报告，是否足以让陌生玩家理解仍由人工试玩验收；
- 战后补充、一项荣誉和一项装备取舍；
- 多套开局前锁定的敌方计划模板；
- 正式命令回执、警报音频和更清晰的地形表现：命令接受/拒绝与新敌情已有不同的程序化短提示音，三种战略区已有独立纹理和双语地形标签；最终音画资产仍属延期内容；
- 试玩事件记录和复盘摘要：结构化事件轨迹、首条有效命令、改令率、情报响应、直接控制比例、接管/归还与单兵诊断尝试均已接入；卡牌识别、行为解释和第二局意愿仍需人工观察。

## 5. 延期内容

- 完整基地建设、矿车经济、逐车生产和科技树；
- 随机牌库、抽牌、卡包和稀有度系统；
- 单兵微操；
- 完整战役、多人、多阵营与大型科技树；
- 自然语言命令和角色化自由对话；
- 最终美术、音频和商业化系统。

## 6. 切片成功路径

```text
读取初始情报
  -> 从军团板向中央下达将领意图
  -> 投入一支总部预备部队或请求侦察
  -> Agent 组织部曲推进和接敌
  -> 新情报迫使玩家调整方向
  -> 玩家直接控制一张部队卡绘制关键路线/阵线
  -> 明确归还将领
  -> 摧毁敌方总部
  -> 战损回写到部队卡
```

A、B、C 只能作为试玩中观察到的常见方案，不能做成剧情选项。玩家必须能自由组合合法命令。

进入该路径前，玩家先在战前编成板提交合法 `ArmyPlan`；战后“再次作战”返回编成板，允许更换编成、战法、姿态和首发关系。

## 7. 自动验收

- 卡牌状态由权威模拟产生，旧快照不随新战损改变；
- 一张部队卡能稳定绑定、选择和命令全部存活成员；
- 玩家接管整张部队卡后，将领不能覆盖成员命令；
- 明确归还后，部队选择安全归队点且不瞬移；
- 两名将领可以同时维持独立目标；
- 资源区严格按周期和控制状态结算；
- 预备队扣除补给并在部署时间后生成绑定实体；
- 未知区域不向双方 AI 泄露真实单位位置；
- 敌方每次改令能追溯到开局计划或合法观测触发器；
- 同一构建、初态、种子和命令序列复现一致的关键事件；
- 常见 A/B/C 与至少三种自由命令组合对三套锁定计划的权威状态黄金矩阵通过；
- 80 个实体下 10 Hz 权威 tick 满足目标硬件预算；
- headless 测试、主场景 smoke 和 Windows debug export 通过。

## 8. 人工试玩标准

陌生玩家应当：

- 30 秒内理解卡牌与真实编队的对应关系；
- 30 秒内通过将领卡或部队卡下达第一条有效命令；
- 能说明一名将领当前为何推进、停下或撤退；
- 根据至少一条带可信度的情报改变部署；
- 至少一次直接控制完整部队卡并明确归还；
- 不尝试寻找单兵微操来解决核心问题；
- 能解释敌方反应来自规则而非临时读选项；
- 愿意用另一种编成、战法或主攻方向再玩一局。

## 9. 当前完成度

首个工程切片已经实现《灰脊矿区》、tick 0 权威战前编成、三名具名将领、四张部队卡、四张战法、将领卡拖向战区与地图任务目标拖动、预备卡拖给所属将领投入、整卡选择/路线/阵线/归还、路线编辑、航路点与阵线端点直接拖动、朝向与预测射界反馈、将领行动/原因/ETA/风险/退出条件反馈、自动资源区、预备部署、支援、地形、情报、三套开局锁定敌方计划、独立西部装甲先遣与时间表佯攻、A/B/C 加三种自由命令组合对三套计划的 18 场黄金矩阵、40/80/120 基准，以及包含补员、功勋、战役时间、一项荣誉和一项装备的战后再编成闭环。战前板可调整部队隶属、战法、姿态和两张首发卡，非法容量或组合不能开局；自定义首发会改变真实 formation、人口和总部预备关系。会战内将预备卡拖给非所属将领会被拒绝，不会入队或扣除补给；地图精确部署入口继续保留。将领风险只读取阵营接触缓存和未过期结构化情报，并有隐藏真值隔离回归。试玩会在本地 `user://playtests/` 保存有界结构化事件，并在战后显示首次命令、每分钟改令、情报响应、直接控制比例、接管/归还和单兵诊断尝试；标准协议和评估工具可把自动指标与四项人工观察合并为不覆盖原始日志的单局判定。Windows 1280×720 完整 HUD 的 80 实体 30 秒与 480 秒工程压力夹具均已通过 60 FPS P95 和长期稳定性门；120 实体常态与 120 实体加 160 常驻弹丸的短时扩展样本也已低于 16.667 ms 数值线，但不扩大正式验收范围。默认开局为 20 个友方加 14 个敌方实体，满预备投入时实际场上为 48 个实体。尚未通过陌生玩家试玩门，也未完成正式关卡人工八分钟会战、80—120 实体实战内容和最终内容表现，因此完整 MVP 状态仍为未完成。
