# WARSEED 玩法系统与内容扩充规格

> 版本：提案 v1，2026-08-19
> 当前政策：D-026 已取消真人证据硬门；D-027 的玩法优先路线决定实施顺序；D-018 至 D-024 按 `DECISIONS.md` 当前状态执行
> 核心目标：增加真正不同的战场决策，而不是只增加名称、数值或地图面积

## 1. 扩充原则

### 1.1 保持不变的核心

- 玩家是军团指挥官，不是逐车操作员；
- 将领卡承载 Agent，部队卡承载真实编队，战法卡承载持续执行方式；
- 战场实体必须真实存在、可受损、可失联、可撤出并回写战损；
- 卡牌始终可见，不引入牌库、抽牌、弃牌或随机手牌；
- 所有玩法效果通过权威命令和系统结算，不允许 UI 或剧情脚本直接改状态；
- 敌我 Agent 只能读取本阵营获得的知识；
- 复杂度优先放在编成、空间、情报和时机，不放在高频微操。

### 1.2 每项新增内容必须回答的问题

新单位、新卡、新地图、新支援或新目标至少回答其中一项：

1. 它让玩家在战前编成中放弃了什么；
2. 它改变了哪个地形或路线问题；
3. 它改变了情报如何获得、保持或失效；
4. 它改变了补给承诺和投入时机；
5. 它改变了将领 Agent 的执行边界；
6. 它产生了哪种可解释的新失败；
7. 它怎样改变下一场会战，而不只是提高面板数值。

只改变攻击、生命或成本而没有新增决策的内容，不应作为独立卡牌进入正式池。

## 2. 推荐规模梯度

| 层级 | 地图 | 时长 | 战略区 | 玩家首发卡 | 总实体目标 | 使用场景 |
|---|---:|---:|---:|---:|---:|---|
| 教学/突袭 | 6144x4096 | 6—10 分钟 | 3—4 | 2—4 | 40—60 | 教学、侦察、护送、短防守 |
| 标准会战 | 8192x5120 | 12—18 分钟 | 5—7 | 4—6 | 60—80 | 战役主力内容 |
| 大型行动 | 10240x6400 | 18—25 分钟 | 7—10 | 6—8 | 80—100 | 章节终局、多轴行动 |

近期正式上限应为 80 个同时活跃实体。现有 Windows 基线证明 80 实体常态可达 60 FPS，120 实体 P95 为 19.931 ms，未通过 16.667 ms 门。在重新优化并复测前，不能以更大地图为理由把 120 写入正式关卡目标。

地图面积不应单独决定时长。关卡必须满足以下节奏预算：

- 首个有意义情报：开战后 10—25 秒；
- 首次争夺或部署承诺：20—45 秒；
- 总部到最近争夺点：20—35 秒；
- 相邻战略区支援时间：20—45 秒；
- 跨越主要战区：90—150 秒；
- 每 25—45 秒出现一个需要理解的新状态；
- 玩家在标准会战中同时处理的主要决策轴不超过 3 条。

## 3. 兵种系统

### 3.1 当前问题

当前战斗单位只有通用生命、护甲、攻击力、射程、射速、弹速、速度和视野。五种会战底层单位已经能形成侦察/突击/火力/工程/运输分工，但无法充分支撑：

- 防空与无人机；
- 重装甲与反装甲；
- 火炮压制与弹药补给；
- 电子战、雷达与隐蔽；
- 混成编队内不同分队的功能；
- “仍有兵力但暂时失去执行能力”的战术状态。

### 3.2 第一阶段新增战斗维度

不要直接进入复杂弹道、穿深角度和逐发部件损坏。第一阶段只增加六个可解释维度：

| 维度 | 作用 | 玩家反馈 |
|---|---|---|
| 目标标签 | `ground/light/armored/air/structure` | 卡面与目标指示明确显示可攻击类别 |
| 伤害标签 | `kinetic/explosive/guided/suppression` | 命中提示和预测射界使用不同图形 |
| 传感器 | 光学、雷达、无人机、声学的探测距离与识别速度 | 报告显示来源、误差与是否持续跟踪 |
| 特征值 | 视觉、热源、雷达特征，决定被发现难度 | 隐蔽/暴露状态显示在卡面而非隐藏数值 |
| 压制 | 不直接杀伤，但降低组织和执行复杂命令能力 | 组织条、受压原因、恢复条件 |
| 弹药 | 仅对火炮、导弹、防空等专业单位使用 | 剩余齐射、补给需求和停火原因 |

不为所有单位增加弹药。突击单位可继续使用抽象无限基础弹药，避免整场变成后勤微操；只有能改变战局的远程/制导火力需要明确弹药窗口。

### 3.3 推荐底层单位定义

| ID 建议 | 角色 | 核心优势 | 明确弱点 | 首次出现 |
|---|---|---|---|---|
| `light_recon_vehicle` | 轻侦察车 | 高速、光学识别、接触后脱离 | 不占点或占点权重低，正面脆弱 | 兼容现有侦察车 |
| `recon_uav` | 侦察无人机 | 跨越部分地形、持续观察、低人员损失 | 受防空/电子战影响，无占点能力 | 扩充行动 05 |
| `mechanized_assault_vehicle` | 机械化突击 | 废墟与近中程稳定、能占点 | 开阔地对重装甲吃亏 | 兼容现有突击车 |
| `heavy_breakthrough_tank` | 重型突破 | 开阔地正面与建筑攻击 | 速度慢、补给高、林地/桥面展开差 | 扩充行动 06 |
| `tank_destroyer` | 反装甲 | 远距离对装甲高威胁 | 对轻目标效率低、近战脆弱 | 扩充行动 06 |
| `self_propelled_artillery` | 自行火炮 | 区域压制、迫使敌人移动 | 需要观察与准备，有有限弹药 | 现有火力卡迁移 |
| `mobile_air_defense` | 机动防空 | 保护区域免受无人机/空中支援 | 对地作用弱，雷达开启会暴露 | 扩充行动 05 |
| `combat_engineer_vehicle` | 战斗工程 | 开路、筑垒、扫除障碍、抢修 | 独立战斗弱 | 兼容现有工程车 |
| `recovery_vehicle` | 战场抢修 | 恢复受损单位和组织，降低战后损失 | 行军慢、需要安全窗口 | 黑井整补卡迁移 |
| `supply_truck` | 运输/补给 | 建立前线节点、恢复专业弹药 | 无武装、需要护卫 | 兼容现有运输车 |
| `electronic_warfare_vehicle` | 电子战 | 降低敌方识别/制导效率、保护撤离 | 效果范围有限、发射时可被定位 | 扩充行动 07 |
| `command_relay_vehicle` | 指挥中继 | 延长将领有效指挥半径、减少改令延迟 | 无直接战力、摧毁后任务受阻 | 章节二后半 |

首个扩充切片只实现 `recon_uav` 与 `electronic_warfare_vehicle` 两种新行为；重装甲、反装甲和专业火炮在目标系统稳定后进入下一批。

### 3.4 角色关系

克制不使用简单环形加成，应由空间和信息共同产生：

```text
侦察/无人机 -> 提供持续识别 -> 火炮/反装甲获得有效目标
电子战/防空 -> 打断持续识别 -> 火力只能压制区域而不能精确打击
突击/工程 -> 在废墟和障碍内逼近 -> 破坏远程火力安全距离
重装甲 -> 在开阔地突破 -> 迫使对方投入反装甲或放弃正面
后勤/抢修 -> 延长持续作战 -> 占用护卫、时间和补给
```

玩家应能从地图、报告与卡面解释上述关系，不能依赖隐藏的“对某类伤害 +25%”。

### 3.5 组织、压制与失能

现有黑井组织度应扩展为所有标准会战可选的卡牌级规则：

- 生命损失和成员失能降低组织；
- 爆炸/压制伤害可以降低组织但只造成少量实体伤害；
- 低组织不会随机逃跑，只改变 Agent 的可执行动作和风险阈值；
- 组织低于 60 时复杂阵线重组变慢；低于 30 时不能执行突破、交替掩护等复杂战法；
- 靠近安全补给节点、脱离接触和装备恢复模块可恢复组织；
- 组织为 0 的部队仍能自卫和撤离，但不能占领新目标或接受强攻命令；
- 所有拒绝必须给出当前组织、所需阈值和合法恢复方式。

失能与死亡分离放到后续阶段。第一阶段可继续把实体 0 HP 视为战场失能，在战后根据回收条件计算永久损失，避免增加战中救援微操。

## 4. 部队卡与卡牌内容

### 4.1 部队卡从单一底盘升级为稳定编制

当前 `UnitCardDefinition` 的单个 `unit_definition_id` 应迁移为稳定条目数组：

```gdscript
class_name UnitCardCompositionEntry
extends Resource

@export var entry_id: StringName
@export var unit_definition_id: StringName
@export var authorized_count: int
@export var formation_role: StringName
@export var replacement_priority: int
```

```gdscript
class_name UnitCardDefinition
extends Resource

@export var definition_id: StringName
@export var display_name_key: StringName
@export var role_tags: Array[StringName]
@export var command_cost: int
@export var deployment_supply_cost: int
@export var deployment_ticks: int
@export var composition: Array[UnitCardCompositionEntry]
@export var compatible_commander_tags: Array[StringName]
@export var intrinsic_ability_ids: Array[StringName]
@export var growth_slot_tags: Array[StringName]
```

`entry_id` 必须稳定，存档不能依赖数组下标。旧 v3 同质卡迁移为单条 `main` 编制并保持现员；不要在同一次存档迁移中重做旧卡的混成比例。旧卡内容重编应作为独立版本迁移，提供明确映射。

| 开路侦察支队 | 4 轻侦察 + 2 电子战 | 隐蔽通路与干扰，正面侦察能力较低 |

| 装甲矛头 | 6 重型突破 + 2 抢修 | 高投入持续突破，跨地形弱 |

第一批新增 4 张即可，不追求一次扩到 24 张：

### 4.4 将领卡

近期不新增将领数量，先把现有五人的差异从文字扩展到类型化行为配置：

```gdscript
class_name CommanderBehaviorProfile
extends Resource

@export var risk_tolerance: float
@export var pursuit_seconds: float
@export var regroup_threshold: float
@export var intel_confidence_required: float
@export var reserve_commit_ratio: float
@export var command_radius: float
@export var order_latency_ticks: int
@export var preferred_role_tags: Array[StringName]
```

性格仍不是纯属性加成。配置只限定候选动作、风险和等待窗口，真正决定来自目标、战法、情报、组织和部曲组成。

### 4.5 战法卡

`DoctrineDefinition` 应增加类型化效果，不再由名称 ID 在世界类中散落分支：

```gdscript
class_name DoctrineEffectDefinition
extends Resource

@export var effect_kind: int
@export var trigger_kind: int
@export var required_role_tags: Array[StringName]
@export var parameters: Dictionary
@export var reason_key: StringName
```

推荐首批效果种类：

- `STAGED_DEPARTURE`
- `REQUIRE_OBSERVED_CONTACT`
- `NARROW_FRONTAGE`
- `FALLBACK_CHAIN`
- `AUTO_ENGINEERING_ROUTE`
- `OVERWATCH_OFFSET`
- `RESERVE_COMMITMENT`
- `DISENGAGE_ON_CONTACT`
- `RALLY_RECOVERY`
- `FOCUS_FIRE_WITH_SIBLING`

效果执行器必须：

- 只读合法阵营快照；
- 输出正常 `GameCommand` 或任务参数；
- 记录触发事实、退出条件和 reason key；
- 在定义加载时验证所需参数；
- 不允许任意脚本路径或表达式从内容数据执行。

### 4.6 荣誉与装备

成长继续使用收益/代价成对设计，并增加兼容标签：

| 槽 | 作用 | 示例限制 |
|---|---|---|
| 荣誉 | 改变组织、风险与补充政策 | 至少参战一次；部分要求完成特定次要目标 |
| 装备 | 改变单位能力或部署成本 | 需要卡牌含对应单位标签；占用整备日和物资 |

新增字段建议：

- `required_card_tags`
- `forbidden_card_tags`
- `replaces_growth_ids`
- `campaign_flag_requirements`
- `battle_effect_ids`
- `debrief_unlock_reason_key`

每卡仍保持一荣誉一装备，暂不增加第三槽。允许在战役整备节点付费替换装备；荣誉不可随意移除，但可以在剧情中升级或转化。

## 5. 地图系统

### 5.1 数据结构拆分

新增独立 `BattleMapDefinition`：

```gdscript
class_name BattleMapDefinition
extends Resource

@export var map_id: StringName
@export var world_bounds: Rect2
@export var cell_size: float = 32.0
@export var tile_scene_path: String
@export var terrain_zones: Array[TerrainZoneDefinition]
@export var navigation_obstacles: Array[NavigationObstacleDefinition]
@export var deployment_zones: Array[DeploymentZoneDefinition]
@export var objective_sites: Array[ObjectiveSiteDefinition]
@export var supply_links: Array[SupplyLinkDefinition]
@export var camera_landmarks: Array[CameraLandmarkDefinition]
```

关键边界：

- 地形区决定移动、视野、隐蔽和展开；
- 目标点决定占领、互动和胜负；
- 经济节点决定产出与补给连接；
- 三者可以重叠，但不能是同一个对象的不同字段；
- 表现 TileMap 与逻辑区共享稳定 ID，加载时验证覆盖与引用；
- 阻挡数据从地图资源加载，`LogicGrid` 不再硬编码 `test_arena`。

### 5.2 地形类型

| 地形 | 移动/展开 | 视野/隐蔽 | 战术作用 |
|---|---|---|---|
| 开阔地 | 快，宽阵完整 | 暴露高，远视线 | 重装甲与远火优势 |
| 废墟 | 慢，编队压缩 | 光学受限，近距识别 | 突击与工程优势 |
| 密林 | 轮式/重装慢 | 隐蔽高，雷达/无人机价值上升 | 侦察、伏击、脱离 |
| 道路 | 高速，路径可预测 | 暴露较高 | 快速增援与伏击轴 |
| 高地 | 上坡慢 | 视野与远程射界提高 | 观察/火力节点 |
| 桥面 | 宽度有限、不可展开 | 高暴露 | 瓶颈与工程目标 |
| 沼泽/泥地 | 重装慢、轻单位较好 | 热源明显 | 兵种路线分化 |
| 工业室内/管廊 | 队形受限 | 非视线传感器弱 | 工程、近战、目标互动 |

地形修正只作用于可说明的行为：速度、展开宽度、视野、特征、射界或组织压力。避免添加玩家无法判断的通用命中率随机修正。

### 5.3 地图制作流程

1. 先画战略区与主要路线图，验证 2—3 个可行方案；
2. 用逻辑区和矩形/多边形完成无美术灰盒；
3. 运行最短路、可达性、部署容量、视线和 80 实体压力检查；
4. 完成目标/经济/敌方计划矩阵；
5. 再制作 TileMap、地标、遮挡轮廓和音景；
6. 最后校准小地图、相机边界、卡牌路线和不同分辨率。

自动校验至少检查：

- 双方总部和所有首发部署区可达；
- 每个主要目标至少有两条路线，除非关卡明确教学瓶颈；
- 部署区能容纳最大合法编制；
- 目标区不与不可通行区完全重叠；
- 供给连接图无悬空引用；
- 敌方计划路径在所有工程开关状态下有明确成功或受阻结果；
- 地图边界与导航网格尺寸一致；
- 相邻战略区的预计支援时间落在设计窗口内。

## 6. 经济模式

### 6.1 统一资源原则

战中继续只使用一种可消费资源：`Supply`。人口/指挥容量是约束，组织/弹药是部队状态，不作为第二种货币。不同经济模式只改变补给来源、连接、上限和风险。

### 6.2 三种关卡经济模板

| 模式 | 补给来源 | 压力 | 适用目标 |
|---|---|---|---|
| 标准战线 | 总部基础收入 + 连通节点周期收入 | 争点与保护连接 | 标准会战、突破 |
| 被围防御 | 有限初始库存 + 空投/运输事件，无稳定基础收入 | 每次支援都是不可逆承诺 | 坚守、撤离、救援 |
| 追击/突袭 | 低基础收入 + 完成阶段目标即时奖励 | 速度换资源，停滞即落后 | 追击、破袭、多阶段行动 |

不建议把旧矿车经济直接并入主战役。旧基地 RTS 可保留为独立遭遇战或少数建设型支线，但主战役的注意力仍应放在军团指挥。

### 6.3 标准补给线模型

地图资源包含一个从总部出发的无向连接图：

```text
HQ -> 后方节点 -> 中继节点 -> 前线节点
```

节点结算条件：

```text
effective_income = node_yield * ownership_factor * connection_factor
```

- 我方控制且未争夺：`ownership_factor = 1`；
- 中立、敌控或争夺：`ownership_factor = 0`；
- 与己方总部存在全我方连通路径：`connection_factor = 1`；
- 使用已部署运输卡建立临时单跳连接：`connection_factor = 0.5`；
- 无连接：`connection_factor = 0`。

不使用连续浮点收入。每个结算周期向下取整并记录来源，UI 显示下一次结算、线路状态和预计收入。

### 6.4 补给支出预算

标准 12—18 分钟会战建议：

| 用途 | 典型成本 | 设计意义 |
|---|---:|---|
| 轻型预备卡 | 2—3 | 快速补轴但战力有限 |
| 重型/混成预备卡 | 4—6 | 主要战役承诺 |
| 侦察/电子支援 | 2 | 购买信息窗口 |
| 工程/机动支援 | 2—3 | 改变路线与到达时间 |
| 火力支援 | 3—4 | 打开突破窗口，有预警/反制 |
| 战场补员/整补 | 3—5 | 保存持续军团，不能无限循环 |

一局中玩家应能做 3—5 次中等承诺或 1 次重部署 + 2—3 次支援。若资源足以无脑按冷却使用全部支援，经济系统即失去意义。

### 6.5 经济反馈

资源栏必须能在一次扫视内回答：

- 当前补给/上限；
- 下一笔基础收入时间；
- 下一笔节点收入及来源；
- 哪条线路被切断或争夺；
- 已承诺但尚未完成的部署成本；
- 当前选中卡或支援是否可支付，以及缺口是多少。

Agent 评估补给时只读取同一权威 `FactionSnapshot`，不得提前消费或隐藏预留。

## 7. 胜利条件与目标系统

### 7.1 三层结算

后续必须分开：

1. **战场结束条件**：何时停止模拟并禁止新命令；
2. **会战结果等级**：决定胜利、惨胜、有序撤离或失败；
3. **战役后果**：改变区域、资源、剧情和下一行动。

摧毁总部可以继续作为一种结束条件，但不再是所有关卡的唯一规则。

### 7.2 类型化目标

首批目标种类：

| Kind | 例子 | 关键参数 |
|---|---|---|
| `DESTROY_ENTITY` | 摧毁总部、雷达、炮兵阵地 | 目标 ID、可见条件 |
| `CONTROL_REGION` | 控制黑井核心 120 秒 | 区域 ID、持续 tick、是否允许争夺中断 |
| `ESCORT_TO_REGION` | 护送运输卡到补给节点 | 卡 ID、最低到达实体数、半径 |
| `WITHDRAW_UNIT_CARDS` | 至少撤出两张残部卡 | 卡集合、最低现员/组织 |
| `BREAKTHROUGH` | 两张战斗卡进入敌后出口 | 区域、卡数、最低组织 |
| `SURVIVE_UNTIL` | 坚守到增援抵达 | tick、必须存活目标 |
| `CONFIRM_CONTACTS` | 确认两个敌方编队后撤离 | 报告类别、可信度、时效 |
| `ACTIVATE_SITE` | 工程卡修复/关闭设施 | 站点 ID、单位标签、互动时长 |
| `PRESERVE_ASSET` | 民用设施/运输线保持一定生命 | 目标 ID、最低生命比例 |

### 7.3 目标组合

不使用任意脚本表达式。采用两层类型化组合即可：

```gdscript
class_name BattleObjectiveSetDefinition
extends Resource

@export var primary_groups: Array[ObjectiveGroupDefinition]
@export var secondary_objectives: Array[BattleObjectiveDefinition]
@export var defeat_objectives: Array[BattleObjectiveDefinition]
@export var time_limit_ticks: int
@export var tie_break_policy: int
```

每个 `ObjectiveGroupDefinition` 只允许 `ALL` 或 `ANY`。禁止递归任意深度；复杂关卡使用阶段切换，而不是不可读的布尔树。

### 7.4 结果等级

推荐统一结果：

| 结果 | 条件概念 | 战役含义 |
|---|---|---|
| 决定性胜利 | 主目标完成 + 关键次要目标 + 损失/时间达标 | 获得额外情报或支援选择 |
| 胜利 | 主目标完成 | 正常推进 |
| 代价胜利 | 主目标完成，但关键资产丢失或损失过高 | 推进但敌方动量/补员压力增加 |
| 有序撤离 | 撤离目标完成，主目标未完成 | 保留军团并开启不同后续节点 |
| 失败 | 失败目标触发或时限结束且未完成退出 | 敌方推进，仍允许战役继续 |

结果等级不应直接按分数相加。先判断主目标和失败条件，再用次要目标、损失、时间修饰结果。

### 7.5 同 tick 结算顺序

每个权威 tick 固定：

1. 结算移动与互动；
2. 结算战斗伤害与死亡；
3. 更新区域、护送、撤离和目标进度；
4. 采集该 tick 同时达成/失败的目标事实；
5. 按关卡 `tie_break_policy` 计算结果；
6. 发布唯一 `BATTLE_CONCLUDED` 事件；
7. 冻结命令队列并生成结算快照。

默认政策：明确完成主目标优先于普通超时；己方关键目标与敌方总部同 tick 被摧毁时按关卡定义，不沿用隐式遍历顺序。

### 7.6 四个现有关卡的目标重构建议

| 会战 | 当前 | 建议主目标 | 次要目标/结果修饰 |
|---|---|---|---|
| 灰脊矿区 | 摧毁总部 | 控制中央中继并摧毁敌前线指挥所，或直接摧毁总部 | 确认敌计划、控制任一侧翼资源区 |
| 断桥回声 | 摧毁总部 | 打开任一渡河轴并让两张战斗卡突破北岸 | 保住主桥、占领高地、工程卡存活 |
| 雾林输线 | 摧毁总部 | 激活前线补给节点并坚守指定时间 | 运输车损失、确认伏击编队、保持线路连通 |
| 黑井反击 | 摧毁总部 | 控制黑井核心至反击窗口结束，或迫使敌主力撤退 | 撤出低组织卡、守住泵站、保留工业设施 |

重构后仍可保留敌方总部作为高风险提前胜利路线，但不再要求每场都穿越全图拆总部。

## 8. 支援系统

当前七种支援行为应统一为数据驱动执行器：

- 区域侦察；
- 紧急筑垒；
- 战场补员；
- 工程开路；
- 火力支援；
- 快速机动；
- 前线后勤。

新增支援候选：

| 支援 | 效果 | 反制/代价 |
|---|---|---|
| 无人机持续监视 | 对一个区域保持高可信报告 | 可被防空驱离或电子干扰 |
| 电子压制 | 降低目标区域敌方识别和制导 | 自身电子战卡需在范围内并暴露 |
| 烟幕走廊 | 降低光学识别，帮助脱离/渡桥 | 同时降低己方精确火力 |
| 紧急空投 | 被围模式恢复少量补给 | 延迟、落点可被观察，冷却长 |

任何支援都必须具有合法目标、预警、持续时间、冷却、成本和至少一种反制。瞬时无预警全图伤害不符合公平信息原则。

## 9. UI 与信息负担

新增系统不能继续把所有状态堆到右侧军团板。推荐分层：

- 默认卡面：现员、组织、弹药状态、当前命令、所属将领；
- 选中卡：编制条目、传感器、暴露/干扰、路线与预计到达；
- 按住详情键或 tooltip：精确数值、成长、兼容和历史；
- 地图：只显示当前选择、相关目标、补给连接和最近重要报告；
- 战役页：只显示区域后果、军团可用性和行动选择，不显示战中细节。

目标 UI 需要区分：

- 主目标/次要目标；
- 未发现/已公开/进行中/受阻/完成/失败；
- 当前进度、保持时间和中断原因；
- 目标完成会结束战斗还是只改变结果等级。

## 10. 数值框架

### 10.1 单位预算

以现有突击车为 1.0 战力基准，只用于早期配置检查：

| 角色 | 正面战力预算 | 信息/支援预算 | 补给负担 |
|---|---:|---:|---:|
| 轻侦察 | 0.45—0.65 | 高 | 低 |
| 机械化突击 | 0.9—1.1 | 低 | 中 |
| 重型突破 | 1.4—1.7 | 低 | 高 |
| 反装甲 | 0.8—1.0 泛用 / 1.5 对装甲 | 中 | 中高 |
| 自行火炮 | 0.6 近战 / 1.4 有观察窗口 | 中 | 高、有限弹药 |
| 工程/抢修 | 0.2—0.5 | 高 | 中 |
| 防空/电子战 | 0.3—0.6 对地 | 高 | 中 |
| 运输/中继 | 0—0.2 | 高 | 低到中 |

最终平衡不能只看该预算。必须在开阔、废墟、林地、桥梁和无情报五类对照场景中验证。

### 10.2 卡牌预算

一张卡的总价值由以下组成：

```text
战斗实体价值
+ 侦察/工程/后勤能力价值
+ Agent 协同与内置能力价值
- 部署补给
- 指挥容量
- 部署时间
- 地形和目标限制
```

高价值混成卡必须同时占用更高指挥容量、补给或更长部署时间，不能只提高所有维度。

### 10.3 关卡平衡证据

每张新地图至少需要：

- 所有敌方锁定计划 × 5 类主动策略的前 200 tick 确定性窗口；
- 所有敌方锁定计划 × 3 类完整策略的全局结局测试；
- 故意失败和有序撤离各至少一个可达案例；
- 一组无新单位的旧编成通关/失败边界；
- 一组使用新单位但错误地形/错误任务的失败案例；
- 60—80 实体 Windows 实渲；
- 至少一轮陌生玩家，不以自动策略胜率替代理解度。

## 11. 内容生产模板

每个新会战在进入实现前必须有一页规格，包含：

1. 一句话战术问题；
2. 主目标、失败条件和结果等级；
3. 地图尺寸、路线图、战略区、地形区和补给连接；
4. 玩家可用将领、卡牌、首发和预备；
5. 三套敌方锁定计划及可被发现的线索；
6. 新机制、复习机制和明确不使用的机制；
7. 经济预算和关键时间窗口；
8. 预期的三种合法解决方案；
9. 主要失败模式与反馈；
10. 自动测试、性能和人工试玩门。

没有三种可解释方案的会战，应继续调整地图和目标，而不是通过隐藏敌方加成制造变化。
