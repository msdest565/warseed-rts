# WARSEED 后续扩充设计文档索引

> 基线日期：2026-09-07
> 适用对象：产品、系统设计、关卡、叙事、程序、测试与内容制作
> 文档性质：基于当前工作区的后续开发提案；除既有 Accepted 决策外，新增方向均须经过阶段门后再转为实现承诺
> 状态说明：D-026 已取消真人证据硬门，D-027 已启用玩法优先路线；最新阶段以 [`AI_DEVELOPMENT_STATE.md`](AI_DEVELOPMENT_STATE.md) 为准。

## 1. 文档目的

本组文档回答五个不同问题：

1. 当前游戏实际上已经做到什么，哪些只是文档目标或测试夹具；
2. 兵种、地图、经济、卡牌和胜利条件怎样扩充，才不会破坏“常驻军团卡牌 + 将领 Agent + 部队卡级控制”的核心；
3. 战役地图和剧情如何承接现有四场会战，并形成可持续生产的内容结构；
4. 这些设计应按什么工程顺序实现，怎样迁移存档、验证数据并控制性能风险。
5. AI 如何判断当前阶段、领取工作项、执行验证并把结果可靠交给下一名开发代理。

本组文档不替代已有产品原则。以下既有约束继续有效：

- 卡牌持续存在，不抽牌、不洗牌，不引入随机手牌或稀有度卡包；
- 部队卡对应真实战场编队，最低正式操作粒度仍是一整张部队卡；
- 玩家与 Agent 使用同一命令、资源、视野和战斗规则；
- 玩家直接控制优先，只有明确归还后 Agent 才能重新接管；
- 敌方计划在读取玩家行为前锁定，反应只能使用合法阵营知识；
- 核心战斗离线可运行，不依赖语言模型或云服务。

## 3. 当前结论摘要

WARSEED 已经拥有可信的工程垂直切片，而不是概念原型：四场行动、战前编成、五名将领、十二张部队卡、十二张战法、十二项成长、七种支援行为、战后持续军团、锁定敌方计划、公平情报和完整测试工具链均已存在。

但“内容数量达到 4/5/12/12”不等于玩法已经有同等数量的差异。当前主要瓶颈为：

- 十二张部队卡在战场层主要复用侦察、突击、导弹、工程和运输五种底层单位；
- `UnitCardDefinition` 只能引用一种单位定义，无法表达真正的混成营、护卫关系或专业分队；
- 战斗只有生命、护甲、攻击、射程、射速和弹速，缺少压制、弹药、传感器、隐蔽、伤害类别与装甲方向等可组合维度；
- 四场会战的权威胜负仍统一为摧毁指挥中心，超时统一失败；护送、开路、撤出和组织度是局部机制，不是独立主目标；
- 会战经济已形成补给闭环，但资源区只按占领与固定周期结算，尚无战线连接、补给中断或不同任务经济模板；
- 四张地图仍以程序化灰盒和矩形阻挡为主，`MapDefinition` 仍硬编码为 `test_arena`，没有正式的地图资产/地形区/部署区数据管线；
- 当前跨局状态能保存战损、组织、荣誉和装备，但没有战役节点、分支、区域控制、剧情标记、敌方战役计划或章节结算；
- 自动化可以证明确定性、命令合法性和流程闭环，但现有 72 案例审计的主动策略主要运行前 200 tick，不能当作完整对局胜率证据；
- 真人 P6.7 仍未执行，但 D-026 已将其改为可选研究；当前通过完整对局代理、因果指标和产品审查控制横向扩充风险。

## 4. 推荐产品目标

后续版本不应简单追求“更多卡牌和更大的图”，而应把现有工程切片升级为一个 12 场行动、3 章结构、可分支但不重运营的单机战役：

| 维度 | 当前 | 下一可交付目标 | 长期上限建议 |
|---|---:|---:|---:|
| 正式会战 | 4 | 6（含两种新胜利条件） | 12 主线 + 3 可选行动 |
| 底层战斗单位定义 | 会战有效 5 种 | 10 种明确角色 | 12—16 种 |
| 部队卡 | 12 | 16，其中至少 4 张混成卡 | 18—24 张 |
| 将领 | 5 | 保持 5，先做关系与成长 | 6—8 名 |
| 战法 | 12 | 保持 12，先完成数据化效果 | 16—20 张 |
| 荣誉/装备 | 12 | 建立兼容标签与替换规则 | 20—30 项 |
| 单场正式实体 | 48 峰值内容 | 60—80 | 80—100，性能通过后再上调 |
| 地图 | 3 张 6144x4096，1 张 7168x4608 | 8192x5120 标准图管线 | 最大约 10240x6400 |
| 主胜利模板 | 总部摧毁 | 4 类 | 6—8 类可组合目标 |
| 战役状态 | 共享军团记录 | 一章 4—6 节点闭环 | 三章行动图 |

“长期上限”不是必须一次达到的内容承诺。每个新增内容都必须改变一个空间问题、资源承诺、情报判断或 Agent 执行边界。

## 5. 后续开发的强制顺序

1. **灰脊乐趣基准。** 建立完整对局观测、战线/威胁提示、异常驱动指挥和因果复盘。
2. **卡牌战术语法。** 让卡牌改变动作、信息、编制、约束和反制，不继续堆同质倍率。
3. **我方分层 AI。** 建立参谋方案、将领任务图、预备队、撤退和受阻重规划。
4. **敌方行动 AI。** 建立阶段、兵力分配、多轴、牵制和公平可复盘的反应。
5. **行动层与内容生产。** 核心循环达到门后再迁入正式地图、补给、第一章后果和新内容。

完整阶段与工作项见 `GAMEPLAY_REWORK_ROADMAP.md`。跳过前四步直接生产大量地图和卡牌，会在薄弱核心循环上放大制作成本。

## 7. 完成定义

本组文档的落实不能以“新类和新卡已经创建”作为完成。一个扩充版本至少需要同时满足：

- 新单位在底层行为、可见反馈和 Agent 使用方式上有区别；
- 新地图使用正式地图数据，不依赖复制旧场景后修改脚本常量；
- 新经济规则有可解释的收入来源、中断条件和 UI 反馈；
- 新卡牌具备稳定 ID、合法编成、存档迁移和战损回写；
- 新胜利条件由权威目标系统结算，并处理同 tick 冲突与战后结果等级；
- 新剧情节点由战役状态驱动，不通过战场脚本直接改写存档；
- 纯模拟测试、内容校验、场景 smoke、完整结局矩阵和 Windows 实渲均有相应证据；可选真人研究不参与完成判定；
- 所有新规则继续遵守公平阵营知识和统一命令边界。
